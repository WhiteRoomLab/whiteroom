## 7. 管理画面・認証・監査

### 7.1 決定済み

- 管理画面を提供する。
- 管理ユーザーを登録・管理できるようにする。
- **ログイン履歴**と**アクティビティログ**を実装する。
- これらを監査にも利用できるようにする。

### 7.2 提案段階

- 権限モデル：`admin` / `editor` / `viewer` などのロール。
- ユーザー作成方法：管理者による招待・登録（一般公開の自己登録は行わない）。
- 著者プロフィールとの紐付け：ログインアカウントに著者プロフィールのID（任意。6.6.3）を持たせる。投稿の `author` の初期値や、自分のプロフィールを編集できるかの判断に使う。
- 認証：サーバーサイドセッション認証、WebAuthn / PasskeyまたはMFA。
- 記録対象：ログイン成功・失敗、権限変更、記事編集・公開・削除、設定変更、バックアップ操作など。
- 監査操作と実データ変更を、可能な限り同一トランザクションで記録。
- 監査ログへの通常UIからの編集・削除操作を禁止。
- ハッシュチェーンと独立した検証値の保管を組み合わせて改ざん検知を強化。
- 管理画面の到達経路をlocalhost / Unixドメインソケット / VPNなどに限定する。

**注意：** SQLiteに監査データを記録するだけでは、OS・DBの管理権限を奪われた場合の改ざん防止にはならない。改ざん耐性や証跡の外部退避は別途設計が必要。
