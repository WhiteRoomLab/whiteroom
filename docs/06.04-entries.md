### 6.4 エントリー

#### 6.4.1 状態と内容を分ける

| 区分 | 項目 | 説明 |
| --- | --- | --- |
| 状態（エントリー本体） | `id`、`number`（サイト内の連番。WordPressから取り込んだものは元の投稿IDを引き継ぐ）、`type`、`language`、`translationGroup`、`status`、`publishedRevision`（公開中のリビジョン）、`createdAt`（作成日時）、`createdBy`（作成者） | 公開・非公開などの状態。リビジョンを作らずに変わる |
| 内容（リビジョン） | 6.4.2以降の項目すべて | 保存のたびに新しいリビジョンとして追加し、書き換えない |

状態とリビジョンは、別々のJSONの文書にする（案。例は6.11.1）。

状態の項目の値（案）：

| 項目 | 値 |
| --- | --- |
| `id` | エントリーのID（6.7） |
| `number` | 1以上の整数 |
| `type` | `post`・`page` か、サイト設定で定義したタイプ（6.4.4） |
| `language` | サイト設定にある言語コード（6.4.5） |
| `translationGroup` | 翻訳グループのID。翻訳の無いエントリーも、自分だけのグループを持つ |
| `status` | 下記 |
| `publishedRevision` | 公開中のリビジョンのID。`status` が `published` のときだけ持ち、そのときは必須 |
| `createdAt` | 日時（6.7） |
| `createdBy` | ログインアカウント（7章）のID。取り込んだエントリーでは、取り込んだアカウント |

`publishedRevision` 以外は必須。

`status` の値は、公開モデル（12章の論点4）と合わせて決める。それまでは、仮に次の4つにする（6.12の7）。

| 値 | 意味 | WordPress（取り込み。案） |
| --- | --- | --- |
| `draft` | 下書き。公開していない | `draft`、`pending`、`private`、パスワード保護（6.10.1） |
| `published` | 公開中。`publishedRevision` のリビジョンを公開している | `publish` |
| `scheduled` | 予約。予約の日時と予約するリビジョンの持ち方は、公開モデルと合わせて決める（いまは値だけを受け付ける） | `future` |
| `archived` | アーカイブ。公開をやめた | （なし） |

リビジョン自体のIDと、保存した日時・保存した人をリビジョンに持つかどうかは、保存先（3.2）と合わせて決める（6.12の26）。

#### 6.4.2 共通の項目

| 項目 | 型 | 必須 | 説明 | WordPress |
| --- | --- | --- | --- | --- |
| `title` | 1行テキスト | ○ | タイトル（装飾なし） | タイトル |
| `slug` | スラッグ | ○ | URLに使う（6.6.8のURLの規則）。同じ言語・同じタイプの中で一意（固定ページは同じ親の中で一意）。公開後に変えると、旧URLからのリダイレクトを自動で登録する | スラッグ |
| `excerpt` | 複数行テキスト | | 一覧や説明文の既定値（装飾なし） | 抜粋 |
| `featuredImage` | メディア参照（画像） | | 一覧やOGPに使う画像 | アイキャッチ画像 |
| `terms` | オブジェクト | | タクソノミーごとのターム（下記） | カテゴリー、タグ、カスタムタクソノミー |
| `body` | ブロックの列 | | 本文（6.5）。本文を使わないカスタムタイプ（6.4.4）では持たない | 本文 |
| `seo` | オブジェクト | | `title`、`description`、`ogImage`、`noindex`、`canonical`（下記） | SEOプラグインの設定 |
| `fields` | オブジェクト | | カスタムフィールド（タイプの定義に従う。6.4.4） | カスタムフィールド・ACF |

- **必須の項目は、公開（予約を含む）するときに確かめる**（決定済み。6.1）。下書きの保存では、書式と型だけを確かめ、書きかけでも保存できるようにする。カスタムフィールドの必須と、最小の文字数・件数（6.4.4）も同じ。ブロックの必須の属性（画像の `media` など。6.5.4）は、保存のたびに確かめる。
- **スラッグ**は、WordPressが日本語タイトルから自動生成した日本語スラッグも維持できるよう、Unicodeの文字を許可する。新規作成や変更でも、取り込みと同じ文字を使える（決定済み。6.1）。使える文字は、ASCIIでは小文字の英字・数字・`-`・`_`、ASCII以外では文字・結合文字・数字・句読点・記号（Unicodeの一般カテゴリーのL・M・N・P・S。`・`、`（）`、絵文字なども含む）と全角スペース（U+3000。WordPressのスラッグに残るため）。ほかの空白、制御文字、書式文字（ゼロ幅空白、双方向の上書きなど）、私用文字、未割り当ての文字は使えない。小文字（ASCII以外の文字も）とNFCにそろえ、先頭と末尾に `-` は置けない。長さはUTF-8で200バイトまで（ファイル名に収まるように）。正規化では、制御文字を取り除き、小文字にしてからNFCをかける（案。空白を `-` にするなどの置き換えは、管理画面や取り込みが行う）。
- `terms`（案）：キーはタイプが使うタクソノミー（6.4.3・6.4.4）、値はタームのIDの列（空にはせず、同じタームは1回まで）。タームはエントリーと同じ言語のものだけ（6.4.5）。書き出すときは、タクソノミーの名前の順に並べる。`category` の最初のタームは、URLの規則の `{category}` に使う（タームの順序に意味がある）。`{category}` を規則に使うタイプでは、公開（予約を含む）するときに `category` が要る（6.6.8）。
- `seo`（案）：`title` と `description` は1行テキスト、`ogImage` は画像のメディア参照、`noindex` は真偽値、`canonical` は `http`・`https` のURLか `/` で始まるサイト内のパス（`href` の規則に従う。6.5.2。`mailto`・`tel` は不可）。SEOの既定値（タイトルの書式・既定のOGP画像など）は、サイト設定に持つ（6.6.8）。

#### 6.4.3 タイプごとの項目

| タイプ | 追加の項目 | WordPress |
| --- | --- | --- |
| `post`（投稿） | `date`（公開日。表示・並び順・URLに使い、編集できる）、`author`、`sticky`（先頭に固定）。`terms` では標準で `category` と `tag` を使う | 投稿 |
| `page`（固定ページ） | `parent`（親ページ）、`order`（並び順）、`template`（テーマが用意したページテンプレートの名前） | 固定ページ |
| カスタムタイプ | サイト設定で定義した項目（6.4.4） | カスタム投稿タイプ |

項目の値（案）：

- `date`：日時（6.7）。投稿を公開するときは必須にする（6.4.2と同じく公開するときに確かめる）。無いまま公開の操作をしたときは、公開した日時を入れる（WordPressと同じ）。URLの日付（6.6.8の `{yyyy}`・`{mm}`・`{dd}`）は、`date` に書いた時差で数える（サイトのタイムゾーンには直さない）。
- `author`：著者プロフィール（6.6.3）のID。
- `sticky`：真偽値（省略は `false`）。
- `parent`：同じ言語の固定ページのID。自分自身は不可（親をたどった循環は、複数のエントリーにまたがる検証で扱う。6.7）。
- `order`：整数（負の数も可。省略は0）。
- `template`：名前（6.7の名前の規則）。テーマの設定ファイルの `pageTemplates`（5.4.2）にあるかは確かめない。テーマに無いもの（テーマを替えた後など）は、`template` の無い固定ページと同じテンプレートで表示する（5.4.4。6.2の4）。
- ほかのタイプの項目（固定ページの `date` など）はエラーにする。

#### 6.4.4 カスタムタイプとカスタムフィールド

タイプとフィールドの定義は、**テーマではなくサイト設定**に置く。サイト設定のうち、開発者が書くスキーマのファイル（`site/schema.yaml`）に持つ（案。6.6.8）。テーマは、タイプごとのテンプレート（`entry-{type}.html`・`archive-{type}.html`。5.4.4）で「どのタイプをどう表示するか」を宣言するだけにして（テンプレートの無いタイプは、共通の `entry.html`・`list.html` で表示する）、テーマを替えてもコンテンツが壊れないようにする。

```yaml
# 例：site/schema.yaml（スキーマのファイル。6.6.8）
schemaVersion: 1
types:
  works:
    label: 制作実績
    url: /works/{slug}/
    archive: /works/      # 一覧のパス（6.6.8）
    taxonomies: [works_category]
    body: true            # 本文（ブロック）を使う
    fields:
      client:
        type: text
        label: クライアント名
        required: true
        maxLength: 100
      year:
        type: number
        label: 制作年
        min: 1990
        max: 2100
        translatable: false   # 翻訳グループ内で同じ値に保つ
      images:
        type: list
        label: 画像
        of: { type: media, accept: [image] }
        maxItems: 20

taxonomies:
  works_category:
    label: 実績の種類
    hierarchical: false
```

フィールドの型：

| 型 | 内容 | 値（JSON。案） | ACFで近いもの | 段階 |
| --- | --- | --- | --- | --- |
| `text` | 1行テキスト | 文字列（改行とタブは不可） | Text | 1 |
| `textarea` | 複数行テキスト（装飾なし） | 文字列（改行とタブも可） | Textarea | 1 |
| `richText` | 文中装飾つきのテキスト | 文中装飾（6.5.2）の列 | WYSIWYG Editor（簡易なもの） | 1 |
| `blocks` | ブロックの列 | ブロックの列。本文と同じ文書に含め、IDとアンカーは本文と合わせて一意にする（6.5.1） | WYSIWYG Editor、Flexible Content | 1 |
| `number` | 数値（最小・最大を指定できる） | 数 | Number、Range | 1 |
| `boolean` | はい／いいえ | `true`・`false`（`false` は省略と同じ） | True / False | 1 |
| `date`、`datetime` | 日付、日時 | `"2026-10-25"`、日時（6.7） | Date Picker、Date Time Picker | 1 |
| `select` | 選択肢から選ぶ（`multiple` で複数選択） | 選択肢の文字列（`multiple` なら列） | Select、Radio Button、Checkbox | 1 |
| `media` | 画像・ファイルの参照 | メディアのID | Image、File | 1 |
| `link` | URLまたは内部リンク | 6.5.2の `link` と同じ形 | Link、Page Link | 1 |
| `entry` | 他のエントリーの参照（1件・複数） | エントリーのID（`multiple` なら列） | Post Object、Relationship | 1 |
| `term` | タームの参照 | タームのID（`multiple` なら列） | Taxonomy | 1 |
| `group` | 項目のまとまり | オブジェクト（フィールドの名前から値へ） | Group | 1 |
| `list` | 同じ形の繰り返し | 値の列 | Repeater | 1 |
| `color` | 色（テーマのプリセット名、または色コード） | | Color Picker | 2 |

フィールドの定義の項目（案）：

| 項目 | 使える型 | 値 |
| --- | --- | --- |
| `type` | すべて | 上の表の型（必須） |
| `label` | すべて | 1行テキスト（管理画面での名前） |
| `required` | `boolean` と、`list` の項目（`of`）以外 | 真偽値。公開するときに値を必須にする（6.4.2）。`group` の中のフィールドは、その `group` に値があるときだけ確かめる |
| `translatable` | タイプの直下のフィールド | `false` で、翻訳グループの中で同じ値に保つ（6.4.5） |
| `minLength`、`maxLength` | `text`、`textarea` | 0以上の整数。文字数はコードポイントで数える。0は制限なし。`minLength` は公開するときに確かめる |
| `min`、`max` | `number` | 数（値の範囲） |
| `options` | `select` | 選択肢。空でない1行テキストで、重複しない（必須） |
| `multiple` | `select`、`entry`、`term` | 真偽値。複数を選べる（値は列にし、同じものは1回まで） |
| `minItems`、`maxItems` | `list`、`multiple` の `select`・`entry`・`term` | 0以上の整数（件数）。0は制限なし。`minItems` は公開するときに確かめる |
| `accept` | `media` | メディアの種類（`image`・`pdf`）の列。省略はすべての種類 |
| `types` | `entry` | 参照できるタイプの列。省略はすべてのタイプ |
| `taxonomy` | `term` | タクソノミー（必須） |
| `fields` | `group` | フィールドの定義（必須） |
| `of` | `list` | 項目の定義（名前・`required`・`translatable` は持たない。必須） |

- タイプとタクソノミーの定義の項目（案）：タイプは `label`（管理画面での名前）・`url`（エントリーのURLの規則）・`archive`（カスタムタイプの一覧のパス。省けば一覧を出さない）・`taxonomies`・`body`・`fields`、タクソノミーは `label`・`url`（タームの一覧のURLの規則）・`hierarchical` を持つ。`url` を省いたものには、既定の規則を使う（`url` と `archive` は6.6.8）。スキーマのファイルの読み込みでは、定義にないキーと、型の合わない値（`body: yes` など）を、行と列を付けてエラーにする（6.6.8）。
- 定義の検証（案）：型が使わない項目を書くとエラーにする。タイプ・タクソノミー・フィールドの名前は、6.7の名前の規則に従い、同じ階層で重複しない。標準のタクソノミー（`category`・`tag`）を `taxonomies` に同じ名前で書くと、`label` と `url` だけを変える（`hierarchical` は、`false` でも書けない。スキーマのファイルの読み込みでエラーにする。6.6.8）。
- 投稿と固定ページにも、`types` に同じ名前で書いて、カスタムフィールドとタクソノミーを足し、`label` と `url` を変えられる（案）。`archive` と `body` は書けない（投稿と固定ページは、いつも本文を持つ。`body` は、`false` でも、`hierarchical` と同じくスキーマのファイルの読み込みでエラーにする。6.6.8）。投稿は、書かなくても `category` と `tag` を使う。
- 値の読み込みと検証（案）：`fields` は、定義を知らなくても読み込めるように、読み込みでは値ごとにJSONとして正しいことと、空の値でないことだけを確かめ、空白を除いた形で持つ。中身は、検証と正規化のときに定義に従って読む。サイト設定のスキーマを変えた後も、保存済みのリビジョンを読み込める（不整合は検証で一覧にする。6.9）。定義に無いフィールドと、型の合わない値はエラーにする。書き出すときは、フィールドの名前の順に並べる。

#### 6.4.5 多言語

- **1つの言語版 = 1つのエントリー。** 言語版ごとにスラッグ・状態・リビジョンを持ち、別々に公開できる。
- **翻訳グループ。** 同じ内容の各言語版は、同じ `translationGroup` を持つ。1つのグループに同じ言語は1件まで。
- **同期する項目。** `translatable: false` の項目と、サイト設定で同期を選んだ項目（アイキャッチ画像、カテゴリー、公開日など）は、グループ内で同じ値に保つ（Polylang の「同期」設定に相当）。
- **翻訳の作り方。** 既存の言語版を複製して作る。本文中の内部リンクは、リンク先に同じ言語の翻訳があればそちらへ張り替え、無ければ警告する。
- **翻訳が無い場合。** 別の言語の内容を代わりに表示することはしない。言語の切り替えでは、その言語のトップページへ案内する（既定。テーマで変えられる）。
- **言語コード**（案）：BCP 47の言語タグのうち、言語（小文字2〜3文字）、用字（任意。先頭だけ大文字の4文字）、地域（任意。大文字2文字か数字3文字）からなるもの（例：`ja`、`en-US`、`zh-Hant`、`es-419`）。大文字と小文字は、この正規の形にそろえる。エントリーの `language` は、サイト設定にあるものだけ。
- **言語のURL**（案）：言語版は、言語のパス（`/en/` など。既定の言語には付けないが、付けることもできる）の下に置き、URLの規則はすべての言語で共通にする（英語の固定ページで、スラッグが `about` のものは `/en/about/`。6.6.8）。
- **言語ごとのエンティティへの参照**（案）：`terms` とタームのフィールドのターム、固定ページの `parent` は、エントリーと同じ言語のものだけ。リンクと、エントリーのフィールドは、ほかの言語のエントリーも参照できる。
- **同期する項目の制限**（案）：`translatable: false` は、タイプの直下のフィールドにだけ書ける（グループやリストの一部だけを同期することはしない）。言語ごとのエンティティ（エントリー・ターム）を参照しうる型（`richText`・`blocks`・`link`・`entry`・`term` と、それらを含む `group`・`list`）には書けない（同じIDのままでは、ほかの言語版から別の言語のものを参照してしまうため）。同期する値の照合は、複数のエントリーにまたがる検証で扱う（6.7）。
