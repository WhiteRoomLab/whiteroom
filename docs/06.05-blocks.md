### 6.5 本文（ブロック）

#### 6.5.1 ブロックの形

```json
{
  "type": "paragraph",
  "id": "b_9x3v7k5m",
  "variant": "lead",
  "style": {
    "textColor": { "preset": "primary" },
    "backgroundColor": { "value": "#fff4e5" },
    "fontSize": { "preset": "large" },
    "padding": { "top": { "value": "1rem" }, "bottom": { "value": "1rem" } }
  },
  "content": [{ "type": "text", "text": "当社の事業内容をご紹介します。" }]
}
```

| キー | 説明 |
| --- | --- |
| `type` | ブロックの種類（6.5.4〜6.5.6） |
| `id` | 文書内で一意なID。差分の表示、ページ内リンク、見た目のCSS（例：`.b-9x3v7k5m`）、将来の共同編集に使う。部品（下記）には付けない |
| `attrs` | 種類ごとに決まった属性。定義にない属性はエラー |
| `content` | 中身。文中装飾つきのテキスト（6.5.2）、子ブロックの列、テキスト（`code` だけ。JSONの文字列）のどれか（種類ごとに決まり、中身を持たない種類もある）。空のときは書かない |
| `style` | 見た目の指定（6.5.3） |
| `variant` | テーマが定義したスタイルのバリエーション名（WordPressの「ブロックスタイル」に相当。テーマの設定ファイルの `blocks` の `variants`。5.4.2） |
| `className` | 追加のCSSクラス（WordPressの「追加CSSクラス」に相当） |
| `anchor` | ページ内リンク用のアンカー（WordPressの「HTMLアンカー」に相当。見出しには自動で付ける）。文書内で一意 |

ブロックの規則（案）：

- **部品**：`listItem`・`tableRow`・`tableCell` は、ほかのブロックの一部として扱い、`id`・`style`・`variant`・`className`・`anchor` を持たない。見た目は、それを含む `list`・`table` か、`listItem` の中の `paragraph` に指定する。`button` と `column` は部品ではなく、ほかのブロックと同じくこれらを持てる。
- `id` は `b_` と小文字の英数字（`0`〜`9`、`a`〜`z`）8文字（例：`b_9x3v7k5m`）。部品以外のブロックでは必須で、文書内で一意にする。ここでいう文書は、エントリーのリビジョンの本文と、`blocks` 型のカスタムフィールドをまとめたもの。`anchor` も同じ範囲で一意にする（見出しに自動で付けるアンカーは、下記のとおり、描画のときに重ならないように付ける）。
- 自動のアンカー：`anchor` の無い見出しには、描画で、ブロックのIDをアンカーにする（`<h2 id="b_4n8c1w2e">`）。そのIDが、文書のどこかのブロックの `anchor`、前の見出しに付けた自動のアンカーか、前の `html`・`legacy` のHTMLで残した `id`（6.5.4）と同じときは、`<ID>-2`・`<ID>-3`… のうち、使われていない最初のものにする（`anchor` が `b_0000head` の段落のある文書では、IDが `b_0000head` の見出しは `<h2 id="b_0000head-2">`）。文書は上と同じ範囲（本文と、`blocks` 型のカスタムフィールド）で、その中で前から順に付ける。`anchor` のある見出しと、IDの書式の正しくない見出し（検証を通っていないもの）には付けない。自動のアンカーが変わることについては6.12の83。
- `attrs` は、属性をすべて省いたときは書かない。真偽値の属性は、既定と違う値のときだけ書けばよい（既定の値も読み込めるが、書き出すときは省く。既定が `true` の `stackOnMobile` だけは、読んだ値をそのまま書き出す）。
- JSONのキーの順序は問わない（`type` より先に `attrs`・`content` があってもよい）。書き出すときは `type`・`id`・`variant`・`className`・`anchor`・`style`・`attrs`・`content` の順にする。

#### 6.5.2 文中の装飾（インライン）

段落や見出しの中身は、テキストノードの列で表す。HTML文字列は持たない。

```json
[
  { "type": "text", "text": "当社の" },
  { "type": "text", "text": "事業内容", "marks": [{ "type": "bold" }] },
  { "type": "text", "text": "をご紹介します。" },
  { "type": "hardBreak" },
  { "type": "text", "text": "サービス一覧", "marks": [{ "type": "link", "attrs": { "entry": "ent_01JB8Y6T2RG7M4XK9P2D5W8NQ3" } }] }
]
```

インラインのノード：

| ノード | 内容 | 出力 | 段階 |
| --- | --- | --- | --- |
| `text` | テキスト（マークを付けられる） | テキスト | 1 |
| `hardBreak` | 段落内の改行 | `<br>` | 1 |
| `ruby` | ルビ（`base` と `text`） | `<ruby>`、`<rt>` | 2 |

マーク：

| マーク | 出力 | 備考 |
| --- | --- | --- |
| `bold` | `<strong>` | |
| `italic` | `<em>` | |
| `underline` | `<u>` | |
| `strike` | `<s>` | |
| `code` | `<code>` | |
| `subscript`、`superscript` | `<sub>`、`<sup>` | |
| `highlight` | `<mark>` | 文字色・背景色。`variant`（テーマが定義したマーカーなど。テーマの設定ファイルの `marks` の `highlight`。5.4.2）か、`color`・`backgroundColor`（6.5.3と同じ値の形）で指定する |
| `fontSize` | `<span>` | 文中の一部だけ文字サイズを変える（段階2） |
| `link` | `<a>` | 下記 |

マークの規則（案）：

- `hardBreak` にはマークを付けない。
- 1つの `text` に、同じ種類のマークは1つまで。
- `subscript` と `superscript` は併用しない。
- `highlight` には、`variant` か色（`color`・`backgroundColor`）のどちらか一方だけを指定する。

`link` の属性：

- 行き先は `href`（外部URL）、`entry`（エントリーのID）、`media`（ファイルのID。PDFへのリンクなど）のうち**多くても1つ**。どれも無いときは `anchor` が必須で、同じページ内の位置へのリンクになる（案）。
- `anchor`（ページ内の位置）は、`entry` と組み合わせる（そのエントリーの中の位置）か、単独で使う。`href` とは組み合わせず、位置は `href` の中に `#…` で書く。`media` とも組み合わせない（案）。
- `href` は `http`、`https`、`mailto`、`tel` と、`/` で始まるサイト内のパスだけを許可する（`javascript:` などは拒否）。
- `href` の追加の規則（案）：`\` を含むURLは拒否する（ブラウザーは `\` を `/` と同じに扱い、`/\evil.example` が `//evil.example` と同じになるため）。認証情報を含むURL（`https://user:pass@example.com`）も拒否する。`http`・`https` はホストを、`mailto`・`tel` は宛先を省略できない（RFC 6068では正しい `mailto:?to=…` の形も、いまは受け付けない）。国際化ドメイン名（IDN）と、パスなどの中の空白は受け付ける。URLにはNFCをかけない（NFDで書かれたファイル名へのリンクが切れるため）。
- `newTab`（新しいタブで開く）、`rel`（`nofollow`、`sponsored`、`ugc` から選ぶ）。`rel` は配列で、複数を選べる（案。例：`["nofollow", "sponsored"]`）。

描画（案）：

- 入れ子の順：1つの `text` のマークは、外側から `link`・`highlight`・`bold`・`italic`・`underline`・`strike`・`subscript`・`superscript`・`code` の順に入れ子にする（JSONに書いた順によらない）。同じ種類のマークが2つ以上あるもの（検証を通っていないもの）は、最初のものだけを使う。
- まとめ方：隣り合う `text` で、外側から同じマーク（開始タグが同じもの）が続く間は、その要素を閉じずに続け、ほかのマークは閉じてから開き直す。`当社の`（`bold`）・`事業`（`bold` と `italic`）・`内容`（`bold`）は `<strong>当社の<em>事業</em>内容</strong>` に、2つの `text` にまたがる同じリンクは1つの `<a>` になる（`<a href="/services/">サービス<strong>一覧</strong></a>`）。行き先や `newTab` の違うリンクは、別の `<a>` になる。
- `hardBreak`：マークを閉じも開きもせず、前後の `text` の両方に続くマークの中に `<br>` を置く（`<strong>一行目<br>二行目</strong><br>三行目`）。
- `highlight`：テーマにある `variant` は、`<mark class="is-variant-marker">` のようにクラスを付ける。テーマに無いものは `<mark>` にして、警告する（6.2の4）。`variant` の無いものの色（`color`・`backgroundColor`）は、`hl-` と16進数8桁のクラス（`<mark class="hl-065c532e">`）と、ページのCSSのそのクラスの規則にする（6.5.3の出力）。色は、`style` の値と同じく、書式とテーマの許可を確かめ、通らないものは警告して無視する（残る色が無ければ `<mark>`）。`variant` と色の両方を持つもの（検証を通っていないもの）は、色を使わない。
- 文字：`&`・`<`・`>` を `&amp;`・`&lt;`・`&gt;` にし、引用符はそのままにする（`1 < 2 & 3 > 2、"二重引用符"` は `1 &lt; 2 &amp; 3 &gt; 2、"二重引用符"`）。属性の値では、`"`・`'` も `&#34;`・`&#39;` にする。U+0000は、U+FFFDにする。
- リンクの行き先：`entry` はそのエントリーのページ、`media` は公開するファイル。`anchor` は、`entry` があればそのURLの後ろに `#` で付け（`/contact/#form`）、無ければ同じページの中の位置（`#top`）にする。
- サイトのパス：エントリーとメディアのURLは、サイトのURL（6.6.8）からのパスの前に、サイトのURLのパスを付けたもの（`/services/`。`https://example.com/blog` のサイトでは `/blog/services/`。URLの全体が要るもの（フィードなど）では、サイトのURLを付ける）。`/` で始まる `href` も、サイトのURLからのパスとして、同じく前に付ける（`/about/` は `/blog/about/`。6.12の56）。サイトの外のページへは、同じホストのもの（`/shop/` など）も、`https://example.com/shop/` のようにURLで書く。`http`・`https`・`mailto`・`tel` の `href` には、サイトのURLのパスを付けない。
- エンコード：URLは、ASCIIの英字・数字・`-`・`.`・`_`・`~` と、予約文字（`!#$&*+,/:;=?@[]`）と、`%` の後に16進2桁が続くもののほかを、バイトごとに16進の大文字でパーセントエンコードする（`/日記/` は `/%E6%97%A5%E8%A8%98/`、空白は `%20`、`"`・`'`・`<`・`>` は `%22`・`%27`・`%3C`・`%3E`）。ホストのASCII以外の文字も、同じくエンコードする（ブラウザーは、デコードしてから国際化ドメイン名として扱う）。残す文字は、`html/template` のURLの正規化が残すものと同じなので、テンプレートで出力しても変わらない。
- `newTab`：`target="_blank"` を付け、`rel` の先頭に `noopener` を置いて、書いた順の `rel` を続ける（`<a href="https://example.com/ad" target="_blank" rel="noopener nofollow sponsored">`）。
- リンクにできないもの：公開していないエントリー（下書きなど）、無いエントリーとメディア、`href` の規則（上記）に合わないもの（検証を通っていないもの）へのリンクは、`<a>` を付けずに文字だけを残し、警告する（`/6/content/24/marks/0: entry "ent_01JB8Y6T2WT6X9C3E6G9J2K5M8" is not published; rendered without the link`。警告の形は6.8）。画像とボタンの `link` も同じで、画像とボタンは、リンクを付けずに描画する（6.5.4）。

#### 6.5.3 見た目の指定（style）

**値の形**

| 形 | 例 | 意味 |
| --- | --- | --- |
| プリセット | `{ "preset": "primary" }` | テーマが定義した値を名前で参照する。テーマを替えると、新しいテーマの同じ名前の値になる |
| 直接指定 | `{ "value": "#1e73be" }` | 書式を検証した値をそのまま使う |

値はすべて、この2つの形のどちらかで書く（案）。`fontWeight`・`lineHeight`・`border` の `style` も、`{ "value": 700 }`・`{ "value": 1.5 }`・`{ "value": "solid" }` のように書く（値が数になるのは `fontWeight` と `lineHeight` だけで、ほかは文字列）。1つの値に `preset` と `value` の両方は書かない。

余白（`padding`・`margin`）は、`top`・`right`・`bottom`・`left` ごとに上の形で指定する。

**項目**

| 分類 | 項目 | 直接指定で使える値 | 段階 |
| --- | --- | --- | --- |
| 色 | `textColor`、`backgroundColor`、`linkColor` | 色コード（`#rrggbb`、`rgb()`、`hsl()` など） | 1 |
| 色 | `gradient` | なし（プリセットのみ） | 1 |
| 文字 | `fontSize`、`letterSpacing` | 単位付きの長さ | 1 |
| 文字 | `fontFamily` | なし（プリセットのみ。フォントはテーマが用意する） | 1 |
| 文字 | `fontWeight` | 100〜900の整数 | 1 |
| 文字 | `lineHeight` | 0より大きく10以下の数 | 1 |
| 文字 | `fontStyle`、`textTransform`、`textDecoration` | 決まった選択肢 | 2 |
| 余白 | `padding`、`margin` | 上下左右ごとの単位付きの長さ | 1 |
| 余白 | `blockGap`（子ブロックどうしの間隔） | 単位付きの長さ | 1 |
| 枠線 | `border`（`width`、`style`、`color`、`radius`） | 長さ・線種（`solid`、`dashed`、`dotted`）・色コード | 1 |
| 影 | `shadow` | なし（プリセットのみ） | 2 |
| 大きさ | `minHeight` | 単位付きの長さ | 2 |
| 背景画像 | `backgroundImage`、`backgroundSize`、`backgroundPosition` | 画像はメディア参照のみ（URLは不可） | 2 |

プリセットを使えるのは、テーマがプリセットを持つ項目（色・`gradient`・`fontSize`・`fontFamily`・余白）だけにする（案）。`gradient` と `fontFamily` はプリセットだけで書き、`letterSpacing`・`fontWeight`・`lineHeight` と、`border` の `width`・`style`・`radius` は直接指定だけで書く。表の `fontWeight`・`lineHeight` の範囲と `border` の線種も、仮に決めたもの。

長さと色の書式（案）：

- 長さ：`0`、または数と単位（例：`1rem`、`1.5em`、`50%`）。単位は `px`、`rem`、`em`、`%`、`vw`、`vh`。単位を省けるのは `0` だけ。負の値（例：`-1rem`）は `margin` と `letterSpacing` だけで使える。`%` は `border` の太さ（`width`）と `letterSpacing` では使えない。
- 色：`#rgb`、`#rgba`、`#rrggbb`、`#rrggbbaa` と、`rgb()`、`rgba()`、`hsl()`、`hsla()`。関数は、カンマ区切り（`rgba(0, 0, 0, 0.5)`）と空白区切り（`rgb(30 115 190 / 50%)`）のどちらでも書ける。`rgb()`・`rgba()` の各成分は0〜255か0%〜100%、`hsl()`・`hsla()` の色相は0〜360（`deg` を付けてもよい）で彩度と明度は0%〜100%、透明度は0〜1か0%〜100%。色名（`red`、`transparent` など）、ほかの色の関数（`hwb()`、`oklch()`、`color()` など）、`calc()`・`var()`・`url()` などのCSS関数は使えない。
- 共通：数は `1`、`1.5`、`.5` のように書き、`+` の符号、指数（`1e2`）、末尾の `.` は使えない。単位と関数名は小文字で書く。

**テーマが決めること**（テーマの設定ファイル `theme.yaml`。5.4.2）

- プリセット（`presets`）：色パレット、文字サイズ、余白の段階、フォント、グラデーション、影。値はCSSの値で書き、直接指定と違って `clamp()` なども書ける（5.4.3）。
- ブロックごとに使える項目（`styles` と、`blocks` の `styles`。例：`code` では文字サイズと背景色だけ）。
- 項目ごとに直接指定を許すかどうか（`custom`。例：色はパレットからだけ選ばせる）。色・文字サイズ・余白の段階の種類ごとに決める。直接指定だけで書く項目（`letterSpacing`・`fontWeight`・`lineHeight` など）を使わせないときは、`styles` から外す。

例：テーマの設定ファイル（全体の例は5.4.9）

```yaml
schemaVersion: 1
presets:
  color:
    primary: "#1e73be"
    accent: "#e85d04"
    muted: "#f5f5f5"
  fontSize:
    small: 0.875rem
    medium: 1rem
    large: clamp(1.25rem, 1rem + 1vw, 1.5rem)
custom:
  color: false
blocks:
  code:
    styles: [fontSize, backgroundColor]
```

**サイト設定で決められること**

- 直接指定を使えるロールを絞れる（例：editor はプリセットだけ、admin は直接指定も可）。制作会社が納品したサイトで、デザインが崩れるのを防ぎたい場合に使う。ロールの権限モデル（7章）と合わせて決めるので、いまはサイト設定に持たない（案。6.12の62）。

**検証のタイミング**（案）

- 保存するとき：検証にサイトのテーマの設定（5.4.2）を渡すと、書式の検査に続けてテーマと照合し、次のものをエラーにする（渡さなければ照合しない）。
  - テーマが、そのブロックの種類に許していない項目（`blocks` のその種類の `styles`。無ければ最上位の `styles` で、どちらも無ければ、すべての項目を許す。5.4.2）：`/0/style/gradient: the theme does not allow gradient for group blocks`。項目の値の書式が正しくなくても示す。
  - テーマに無いプリセット：`/0/style/fontSize/preset: the theme has no fontSize preset "huge"`（種類の名前は、テーマの設定ファイルの `presets` のキー）。
  - テーマがプリセットだけを許す種類（`custom` を `false` にしたもの）の直接指定：`/0/style/backgroundColor/value: the theme allows only presets for color`。
  - `spacer` の `height`（6.5.4）と `highlight` の色（6.5.2）も、プリセットと直接指定を同じく照合する（`style` の項目ではないので、`styles` とは照合しない）。
  - 書式の正しくない値は、テーマと照合しない（書式のエラーだけを示す）。1つのブロックの中では、`style` の書式、`blockGap` の構造の規則（下記）、`style` のテーマとの照合の順にエラーを並べ、属性（`spacer` の `height` を含む）と中身（`highlight` を含む）のエラーは、その後ろに置く。
- 受け付けるもの：取り込みでは、テーマと照合しない。前のリビジョンから変えていない値も受け付ける（テーマを替えた後や、取り込んだ後も、ほかの部分を編集して保存できるように）。前のリビジョンのブロックは、6.7の「取り込みと前のリビジョン」と同じく `id` で探し、位置は問わない。
  - `style` の項目：前のリビジョンの、同じ `id` で同じ種類のブロックに、同じ値の同じ項目があれば受け付ける。項目の全体で比べる（`padding` の1辺を変えると、`padding` のすべての辺を照合する）。
  - `spacer` の `height`：前のリビジョンの同じ `id` のブロックが、同じ `height` の `spacer` なら受け付ける。
  - `highlight` の色：前のリビジョンのどこか（ブロックの文中装飾・`citation`・`caption` と、`richText` 型のフィールド。どれも入れ子の中も）に、同じもの（`variant` と2つの色がすべて同じもの）があれば受け付ける。
- `blockGap`：子ブロックを持つ `list`・`quote`・`buttons`・`columns`・`column`・`group` だけが持てる。テーマによらない構造の規則で、ほかの種類（`table` も）はエラーにし（`/0/style/blockGap: blockGap is not allowed for paragraph blocks`）、その `blockGap` はテーマと照合しない。
- 照合しない名前：バリエーション（ブロックと `highlight`）、固定ページの `template`、メニューの `location`、画像の `size` は、いまも名前の書式だけを確かめる（6.12の91）。
- ビルドするとき（テーマを替えた後など）：描画は、書式の正しくない値と、テーマが許さない値（保存のエラーと同じもの。取り込んだ値と、変えずに残した値も）を、警告して無視する（6.2の4）。警告の文は、エラーの文の後ろに `; ignored` を付けたもの（`/0/style/fontSize/preset: the theme has no fontSize preset "huge"; ignored`、`/0/style/blockGap: blockGap is not allowed for paragraph blocks; ignored`）。テーマが許さない項目は、値を確かめずに、項目の警告だけを示す。

**出力**（案）

- ページのCSSとサイトのCSS：インラインの `style` 属性と `<style>` の要素は使わず、見た目はCSSのファイルにして `<link>` で読む（インラインのスタイルを禁止する厳格なCSP（`style-src 'self'`）と両立できる）。CSSは次の2つに分ける。描画はCSSの中身を作り、ファイルのパスと、ページのテンプレートへの渡し方は、ビルドで決める（6.12の88）。
  - ページのCSS：ページごとの、ブロックと `highlight` の規則（下記）。ファイルの名前は、中身のハッシュから作る（同じ中身のページは、同じファイルを使える）。
  - サイトのCSS：サイトで1つの、テーマのプリセットの変数（5.4.3）と、本体が付けるクラスのCSS（6.5.4）。
- 読み込む順：サイトのCSS、テーマのCSS（`assets/`。5.4.7）、ページのCSSの順にする。テーマのCSSは、本体のクラスのCSSを上書きできる（6.5.4）。
- `!important`：ページのCSSの宣言には、`border` の線種の既定（下記）を除いて、すべて `!important` を付ける。編集者の選んだ値が、テーマのCSSの詳細度によらずに効くように。テーマのCSSは、編集者の値を上書きできないので、画面の幅で変えたい値は、プリセットで書く（テーマが、プリセットの値に `clamp()` などを書くか、テーマのCSSのメディアクエリーの中で、変数の値を変える。6.12の93）。
- ブロックの規則：規則のあるブロック（`style` か、長さと数の見た目の属性（6.5.4）の値が残ったもの）には、IDの `b_` を `b-` にしたクラスを付け（6.5.4。IDの正しくないものと重なったものは6.8）、そのクラスで次の規則を、この順に作る（宣言の無い規則は作らない）。

  2. `:where(.b-<ID>)`：`border` の `width` か `color` が残り、`style` が残らないときの `border-style: solid`（線を表示するための既定。`!important` を付けず、詳細度を0にして、テーマのCSSが書いた線種を優先する）。
  3. `.b-<ID> :where(a)`：`linkColor`。ブロックの中のリンクの `color`（6.12の90）。
  4. `.b-<ID> img`：画像の `width`・`aspectRatio`（6.5.4）。
  5. `.b-<ID> > *` と `.b-<ID> > * + *`：子ブロックの間の `blockGap`（下記）。

補足：

- **見出し**：H1はタイトル専用にする。本文中のH1は、取り込み時にH2へ変える。
- **画像**：`alt` は必須（装飾目的の画像は `decorative: true` にして、`alt` を書かない）。WordPressの画像は `alt` が無いことが多いため、取り込み時は `alt` の無い画像も受け付けて警告にとどめ、未設定の一覧を出す。取り込んだ後の編集でも、`media` を変えずに `alt` が無いままの画像は受け付ける（案。6.7）。エディタで画像を置くときは、メディアの `alt` を初期値にする（案）。`alt` の無い画像の描画では、メディアの `alt` を使う（案。順序は6.6.2）。
- **囲み枠**：日本のテーマでよく使われる「ボックス」「注意書き」「キャプション付きの枠」は、`group` に `style`（背景色・枠線）を指定するか、テーマのバリエーションと `label` で表す。
- **埋め込み**：`provider` は許可リスト（YouTube、Vimeo、X、Googleマップなど）にあるものだけ使える。埋め込み用のHTMLはURLから決まった形で生成し、ビルド時に外部へ問い合わせない。iframeのHTMLが貼り付けられた場合は、エディタや取り込みが `src` だけを取り出して `url` に入れる（モデルにはURLだけを持ち、iframeのHTMLは持たない）。許可リストと、受け付ける `url` の形（案）：
  - `youtube`：YouTubeの動画（`youtube.com` の `/watch?v=…`・`/embed/…`・`/shorts/…`・`/live/…` と、`youtu.be/…`）。`youtube.com` の代わりに `www.youtube.com`・`m.youtube.com`・`www.youtube-nocookie.com` も使える。再生リストのURLは受け付けない。
  - `vimeo`：Vimeoの動画（`vimeo.com/数字`、限定公開の動画の `vimeo.com/数字/16進の文字列`、`player.vimeo.com/video/数字`）。`vimeo.com` の代わりに `www.vimeo.com` も使える。
  - `x`：Xの投稿（`x.com/ユーザー名/status/数字`）。`x.com` の代わりに `twitter.com` も使え、どちらも `www.`・`mobile.` を付けてもよい。
  - `googleMaps`：Googleマップの「地図を埋め込む」で得られるiframeの `src`（`www.google.com/maps/embed?pb=…`）。
  - どれも `https` だけで、ポート番号は付けられない。`v`・`pb` のほかのクエリ（YouTubeの再生位置の `t` など）は問わない。
- **`html`**：既定では使えない（サイト設定の `allowHtml` で有効にする。6.6.8）。作成・編集はadminだけができ、変更は監査ログに記録する。有効にしていないサイトでは、取り込んだものも、前のリビジョンにあったものもエラーにする（案）。検証では中身のHTMLを確かめず、検査とサニタイズは描画のときに行う（案。スクリプトの扱いは6.12の6）。
- **`legacy`**：取り込み専用で、エディタからは作れない。中身は厳格にサニタイズしてから表示し、管理画面で「要確認」として一覧にする。改ざんされたWordPressから移行する場合に本文へ埋め込まれている不正なスクリプトも、ここで取り除かれる。検証では、取り込みのときと、前のリビジョンの同じ `id` の `legacy` から `html` と `reason` を変えていないときだけ受け付ける（案）。

描画（案）：

- ブロックは、テーマのブロックのテンプレート（5.4.4）か、それが無い種類は本体の既定のテンプレート（6.8）で、HTMLにする。下の表は、既定のテンプレートのHTML。
- `id` と `class`：部品以外のブロックでは、最初の要素に、`id`（`anchor` か、見出しの自動のアンカー。6.5.1）と `class` を、この順に、値のあるときだけ付ける（表では省く）。`class` には、ページのCSS（6.5.3の出力）に規則のあるブロックではIDの `b_` を `b-` にしたもの（`b_9x3v7k5m` は `b-9x3v7k5m`。IDの正しくないものと重なったものは6.8）、見た目の属性のクラス（下記）、テーマにあるバリエーションでは `is-variant-<名前>`、`className` を、この順に空白で区切って並べる（`<p id="intro" class="b-0paragr1 has-text-align-center is-variant-lead intro">`）。テーマに無いバリエーション（5.4.2の `blocks` の `variants`）は、クラスを付けずに警告する（6.2の4）。部品の `tableCell` には、`textAlign` のクラスだけを `class` に付ける（`colspan`・`rowspan` より前に。`<td class="has-text-align-center">`）。
- 子ブロック：子ブロック（リストの項目と、表の行とセルも）は、行を分けて並べ、親の開始タグ（`group` の `label` の `<header>` は、その後ろに続ける）の後ろと、終了タグの前で改行する（`listItem` の `<li>` の後ろと `</li>` の前は除く。下の例）。文中装飾は改行しない。中身の無い要素は、開始タグと終了タグを続ける（`<div></div>`）。
- エスケープ：テンプレートが出力する値は、`html/template` が文脈に合わせてエスケープする（文中装飾は6.5.2）。

例：`start` が3の番号付きのリストで、最初の項目に入れ子のリストがあるもの：

```html
<ol start="3">
<li><p>First</p>
<ul>
<li><p>Nested</p></li>
</ul></li>
<li><p>Second</p></li>
</ol>
```

- 見た目の属性：`textAlign`・`justify`・`verticalAlign`・`stackOnMobile`・`layout`・`align`、ボタンとカラムの `width`、`spacer` の `height`、画像の `size`・`width`・`aspectRatio` は、テンプレートのデータでは、書いた値のまま渡す（5.4.4）。`class` とページのCSSには、下記の「見た目の属性（案）」のとおりにする。画像の `size` と `srcset` は、公開する画像（6.6.2）と合わせて作る。
- 画像：`src` は、メディアの公開するファイルのURL（6.5.2のサイトのパス）。`alt` は6.6.2の「描画に使う `alt`」のとおりで、`decorative` の画像は `alt=""`。`alt` がどこにも無い画像は、`alt` の属性を付けずに描画し、警告する（空の `alt` は、装飾の画像を表すため）。
- 埋め込み：iframeのHTMLは、提供元ごとに決まった形で作り、ビルドでは提供元に問い合わせない（補足）。iframeには、`src`・`width`・`height`・`title`・`loading="lazy"`・`allow`・`referrerpolicy`・`allowfullscreen` を、この順に付ける（`allow` と `referrerpolicy` は、値のあるときだけ）。`title` は `caption` の文字（`hardBreak` は空白）で、`caption` が無ければ提供元の名前（`YouTube`・`Vimeo`・`Google Maps`）。大きさは仮の値（6.12の85）。
  - `youtube`：`src` は `https://www.youtube-nocookie.com/embed/<動画のID>`（プライバシー強化モード）。URLのほかのクエリ（再生位置の `t` など）は捨てる。560×315で、`allow` は `accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share`、`referrerpolicy` は `strict-origin-when-cross-origin`（YouTubeは、リファラーの無い再生を拒むため）。
  - `vimeo`：`src` は `https://player.vimeo.com/video/<数字>?dnt=1`（限定公開の動画は `?h=<16進の文字列>&dnt=1`）。`dnt=1` で、プレーヤーに閲覧を記録させない。640×360で、`allow` は `autoplay; fullscreen; picture-in-picture; clipboard-write; encrypted-media; web-share`、`referrerpolicy` は `strict-origin-when-cross-origin`。
  - `googleMaps`：`src` は `url`（6.5.2のとおりエンコードしたもの）。600×450で、`allow` は無く、`referrerpolicy` は `no-referrer-when-downgrade`（Googleマップの埋め込みのコードと同じ）。
  - `x`：iframeにせず、投稿へのリンクにする（`<p><a href="https://x.com/jack/status/20">https://x.com/jack/status/20</a></p>`）。Xの公式の埋め込みは、Xのスクリプトをページの中で動かすので使わない（6.12の21）。
  - 例（`caption` が `Our video` のYouTubeの動画）：`<iframe src="https://www.youtube-nocookie.com/embed/dQw4w9WgXcQ" width="560" height="315" title="Our video" loading="lazy" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" referrerpolicy="strict-origin-when-cross-origin" allowfullscreen></iframe>`
- `html`・`legacy`：`html` 属性のHTMLを、サニタイズして出力する（テンプレートは使わない。下記の「`html`・`legacy` のサニタイズ（案）」）。
- 描画しないもの：メディアの無い `image`・`file`、画像でないメディアを指す `image`、フォームの無い `form`、`provider` か `url` を埋め込めない `embed`（検証を通っていないもの）と、サニタイズできない `html`・`legacy`（下記）は、描画せず（何も出力しない）、警告する。リンクにできない `link`（6.5.2）のある画像とボタンは、リンクを付けずに描画する。
- 正しくないコンテンツ：描画は、検証（6.7）を通ったコンテンツを受け取る前提だが、通っていないもの（知らない種類のブロックやマークなど）でも、正しく入れ子になった安全なHTMLを返し、描画できないものは、警告して飛ばす（検証の誤りを、すべて警告するわけではない）。見た目の値（`style` と見た目の属性）は、検証と同じ規則で確かめ、通らないものは、クラスにもCSSにもせずに警告する（6.5.3・下記）。

見た目の属性（案）：

- クラス：選択肢の決まった属性は、決まったクラス（下の表）にして、`class` に並べる（データの `.Class`。5.4.4）。値ごとのクラスの名前は、属性ごとの前置き（`has-text-align-` など）に、値をケバブケースにしたもの（`spaceBetween` は `space-between`、ボタンの `25%` は `%` を除いた `25`）を続けたもので、本体の接頭辞は付けない。属性の値を、そのままクラスに入れることはしない。1つのブロックのクラスは、表の順に並べる。

| ブロック | 属性 | クラス |
| --- | --- | --- |
| `paragraph`、`heading`、`tableCell` | `textAlign` | `has-text-align-left`・`has-text-align-center`・`has-text-align-right` |
| `image` | `align` | `alignleft`・`aligncenter`・`alignright`・`alignwide`・`alignfull` |
| `buttons` | （いつも付ける） | `is-layout-row` |
| `buttons` | `justify` | `is-content-justification-left`・`is-content-justification-center`・`is-content-justification-right`・`is-content-justification-space-between` |
| `button` | `width` | `has-width-25`・`has-width-50`・`has-width-75`・`has-width-100` |
| `columns` | （いつも付ける） | `is-layout-columns` |
| `columns` | `verticalAlign` | `are-vertically-aligned-top`・`are-vertically-aligned-center`・`are-vertically-aligned-bottom` |
| `columns` | `stackOnMobile` | `false` なら `is-not-stacked-on-mobile` |
| `column` | `verticalAlign` | `is-vertically-aligned-top`・`is-vertically-aligned-center`・`is-vertically-aligned-bottom`・`is-vertically-aligned-stretch` |
| `group` | `layout` の `type` | `is-layout-flow`・`is-layout-row`・`is-layout-stack`・`is-layout-grid` |
| `group` | `layout` の `justify` | `row` では `is-content-justification-left`・`is-content-justification-center`・`is-content-justification-right`・`is-content-justification-space-between`、`stack` では `is-content-justification-left`・`is-content-justification-center`・`is-content-justification-right`・`is-content-justification-stretch` |
| `group` | `layout` の `verticalAlign` | `row` では `are-vertically-aligned-top`・`are-vertically-aligned-center`・`are-vertically-aligned-bottom`・`are-vertically-aligned-stretch`、`stack` では `are-vertically-aligned-top`・`are-vertically-aligned-center`・`are-vertically-aligned-bottom`・`are-vertically-aligned-space-between` |
| `group` | `layout` の `nowrap` | `is-nowrap` |
| `group` | `align` | `alignwide`・`alignfull` |

- 属性の規則：長さと数の属性は、ページのCSSのブロックの規則にし（6.5.3の出力）、`!important` を付ける。`.b-<ID>` の規則では、`style` の宣言の後ろに置く。
  - 画像の `width`・`aspectRatio`：`.b-<ID> img` の規則に、`width`、`aspect-ratio` と `object-fit: cover`（縦横比を変えた画像は、切り抜いて表示する）、`height: auto`（どちらかがあるとき）を、この順に書く。
  - カラムの `width`：`.b-<ID>` の `flex-basis` と `flex-grow: 0`（`width` の無いカラムは、残りの幅を等分する。下記。`padding` のあるカラムの幅は6.12の95）。
  - `spacer` の `height`：`.b-<ID>` の `height`。プリセットと直接指定は、`style` の値と同じく、テーマのプリセットと `custom` の `spacing` とで照合する（6.5.3）。
  - `grid` の `columns`・`minColumnWidth`：`.b-<ID>` の `grid-template-columns` にする。`columns` だけなら `repeat(<columns>, minmax(0, 1fr))`（列の数を決める）、`minColumnWidth` だけなら `repeat(auto-fill, minmax(min(<minColumnWidth>, 100%), 1fr))`（その幅以上の列を、入るだけ並べる）、両方なら `repeat(auto-fill, minmax(max(min(<minColumnWidth>, 100%), (100% - <columns - 1> * <間隔>) / <columns>), 1fr))`（`minColumnWidth` 以上の列を、多くても `columns` 列並べる）。`<columns - 1>` は計算した数で、`<間隔>` は、そのグループの残った `blockGap` の値（プリセットは `var()`）か、無ければグリッドの間隔の既定の `0.5em`（6.12の92）。どちらも無いグリッドは、本体のクラスのCSSの既定（下記）で並べる。

例：`columns` が3、`minColumnWidth` が `10rem`、`blockGap` がプリセットの `20` のグリッド（`every-style.json` の、IDが `b_00grid03` の `group`）の規則：

```css
.b-00grid03 {
  gap: var(--spacing-20) !important;
  grid-template-columns: repeat(auto-fill, minmax(max(min(10rem, 100%), (100% - 2 * var(--spacing-20)) / 3), 1fr)) !important;
}
```

- 本体のクラスのCSS：表のクラス（`align` のクラスを除く）のCSSは、本体が書き（`internal/render/classes.css`）、サイトのCSSに入れる（6.5.3の出力）。テーマのCSSは、後から読むので、同じ詳細度の規則で上書きできる。
  - 文字の配置：`has-text-align-left` などは、`text-align`。
  - 並べ方：`is-layout-row` は、横に並べて、入らなければ折り返す（`display: flex`・`flex-wrap: wrap`・`align-items: center`。`is-nowrap` は `flex-wrap: nowrap`）。`is-layout-stack` は、縦に積む（`display: flex`・`flex-direction: column`・`align-items: flex-start`）。`is-layout-grid` は、12rem以上の列を、入るだけ並べる（`display: grid`・`grid-template-columns: repeat(auto-fill, minmax(min(12rem, 100%), 1fr))`）。`is-layout-columns` は、横に並べて、折り返さない（`display: flex`）。`is-layout-flow` には、CSSが無い（通常の並び）。
  - 間隔：`row`・`stack`・`grid` は `gap: 0.5em`、カラム群は `gap: 2em`。`:where()` の中に書いて詳細度を0にし、テーマのCSSが上書きしやすいようにする（例は5.4.9）。この4つの並べ方の子は、`margin` を0にする（間隔は `gap` で空ける）。
  - 見出し：`group` の `label` の `<header>` は、子ブロックの並びの外に置く。`row` では1行を占め（`flex-basis: 100%`）、`grid` ではすべての列にまたがる（`grid-column: 1 / -1`）。HTMLは変えない（6.12の87）。
  - 配置：`row` では、`is-content-justification-*` が `justify-content`、`are-vertically-aligned-*` が `align-items` になり、`stack` では逆に、`is-content-justification-*` が `align-items`、`are-vertically-aligned-*` が `justify-content` になる。カラム群の `are-vertically-aligned-*` は `align-items`、カラムの `is-vertically-aligned-*` は `align-self`。値は、`left`・`top` が `flex-start`、`right`・`bottom` が `flex-end` で、`center`・`stretch`・`spaceBetween`（`space-between`）は同じ名前の値。
  - カラム：カラムは、幅を等分する（`flex: 1 1 0`・`min-width: 0`）。`width` のあるカラムは、ページのCSSで、その幅にして伸ばさない（上記）。
  - 狭い画面：画面の幅が、テーマの `mobileWidth`（5.4.2。省けば781px）以下のとき、`is-not-stacked-on-mobile` の無いカラム群は、カラムを縦に積む（`@media (max-width: <mobileWidth>)` の中で、カラム群を `flex-wrap: wrap` にし、カラムを `flex-basis: 100% !important` にする。`!important` は、ページのCSSのカラムの `width` より優先するため）。
  - ボタンの幅：4つのクラスは、`flex: 1 1 0`・`box-sizing: border-box`・`width: 100%` で、`has-width-25`・`has-width-50`・`has-width-75` は `max-width` を `25%`・`50%`・`75%` に、`has-width-100` は `flex-basis` を `100%` にする（1行を占める）。指定した幅は、最大の幅として働く（6.12の94）。
- `align` のクラス：`alignleft`・`aligncenter`・`alignright`・`alignwide`・`alignfull` のCSSは、テーマが書く（コンテンツの幅を知っているのはテーマなので、本体のクラスのCSSには無い。例は5.4.9）。
- 正しくない値：検証を通っていない属性の値は、クラスにもページのCSSにもせず、`<ブロックのパス>/attrs/<キー>`（`layout` の中のものは `<ブロックのパス>/attrs/layout/<キー>`）で警告して無視する。選択肢に無い値は `unknown textAlign "middle"; ignored`、`layout` の `type` が無いものと知らないものは `missing layout type; ignored`・`unknown layout type "column"; ignored`（`layout` のクラスとCSSを作らず、`layout` の無いグループとして描画する）、`type` に使えないキーは `not allowed for flow layout; ignored`、範囲の外の `columns` は `columns 17 is out of range (1-16); ignored`、正しくない長さと縦横比は、検証のエラーの文の後ろに `; ignored` を付けたもの（`invalid length "300"; ignored`・`negative length "-1px" is not allowed here; ignored`・`invalid aspect ratio "16:9"; ignored`）。`spacer` の `height` は、`style` の値と同じ（6.5.3）。

`html`・`legacy` のサニタイズ（案）：

- 構文解析：`html` 属性のHTMLを、HTMLの仕様（HTML Standard の2026年10月30日の版）の構文解析で、`div` の要素の中身として解析する（ブラウザーの `innerHTML` と同じ、断片の構文解析）。ブラウザーが作るのと同じ木で、残すものを確かめるため。スクリプトを有効にしたブラウザーと同じく解析するので、`noscript` の中身は、要素にならずに文字になる。構文解析は、外部のライブラリに頼らず、自前で実装した（`internal/html`。取り込みで、本文のHTMLをブロックに変換するとき（6.10.2）にも使う）。仕様の変更への追従は6.12の101。
- テスト：構文解析は、html5lib-tests の字句解析のテストと、web-platform-tests の木の構築のテスト（2026年6月に html5lib-tests から移ったもの）で確かめる（木の構築のテストは、スクリプトを有効にしたものと無効にしたもので行う）。どちらも、次のものを除いて、すべて通る。字句解析では、対になっていないサロゲート（Goの文字列には書けない）を含む4件と、XMLに合わせる変換（HTML Standard の13.2.9）を前提にする `xmlViolation.test`。木の構築では、スクリプトを動かす `scripted_*.dat` と、`selectedcontent` の4件（選んだ `option` を `selectedcontent` に写すのは、`option` の要素の処理で、木の構築の外のため）。
- 残す要素：次の要素を残す。HTML Standard の8.6.5にある、ブラウザーのサニタイズ（`setHTML()` など）の安全な既定の設定のHTMLの要素から、文書の要素（`html`・`head`・`title`・`body`）と `main` を除き、`img`・`details`・`summary` を足したもの。
  - `a`・`abbr`・`address`・`article`・`aside`・`b`・`bdi`・`bdo`・`blockquote`・`br`・`caption`・`cite`・`code`・`col`・`colgroup`・`data`・`dd`・`del`・`details`・`dfn`・`div`・`dl`・`dt`・`em`・`figcaption`・`figure`・`footer`・`h2`〜`h6`・`header`・`hgroup`・`hr`・`i`・`img`・`ins`・`kbd`・`li`・`mark`・`menu`・`nav`・`ol`・`p`・`pre`・`q`・`rp`・`rt`・`ruby`・`s`・`samp`・`search`・`section`・`small`・`span`・`strong`・`sub`・`summary`・`sup`・`table`・`tbody`・`td`・`tfoot`・`th`・`thead`・`time`・`tr`・`u`・`ul`・`var`・`wbr`。
  - `h1` は、`h2` にして残す（H1はタイトル専用。補足の「見出し」）。
  - `html` では、`iframe`・`video`・`audio`・`source`・`track` も残す（iframeは6.12の98）。`legacy` では、これらも中身ごと取り除く。
- 取り除く要素：ほかの要素は、取り除く。
  - 中身ごと取り除くもの（中身が、ページの文章にならないもの）：`script`・`style`・`template`・`noscript`・`noembed`・`noframes`・`object`・`embed`・`applet`・`frameset`・`frame`・`select`・`datalist`・`optgroup`・`option`・`textarea`・`title`・`head`・`canvas`・`param`・`base`・`link`・`meta`・`input`・`keygen`。`svg`・`math` の要素（HTMLの名前空間の外の要素）も、中身ごと取り除く（6.12の97）。
  - タグだけを取り除くもの：ほかの要素（`font`・`center`・`main`・`form`・`button`・`label`・`picture`・カスタム要素など）は、タグだけを取り除いて、中身を残す。
  - 深さ：残す要素が256段より深く入れ子になったところは、タグだけを取り除いて、中身を残す（タグを取り除いた要素は、段に数えない）。
  - 残した `iframe` の中身（ブラウザーは表示しない）も取り除く（空白だけのものは、警告しない）。
- コメントなど：コメント・処理命令（`<?…>`）・DOCTYPEは、警告せずに取り除く。
- 残す属性：どの要素でも、`dir`・`lang`・`title`・`id`・`class` を残し、要素ごとに、下の表の属性も残す。ほかの属性（`style`、`onclick` などのイベントハンドラー、`srcset`・`sizes`、`data-*`・`aria-*`・`role`、`hidden` など）は取り除く。値は、URL・`class`・`id`・`target`・`rel`（下記）のほかは、書いたままにする。

- URL：下の表の属性のURLは、6.7のURLと同じく、制御文字（途中にあるものも）と前後の空白を取り除いてから、`href` の規則（`\` を含むもの、認証情報を含むもの、`//` で始まるものなどは拒否する。6.5.2・6.7）と、種類ごとに許すもの（下の表）で確かめ、合わないものは、属性を取り除く。リンクの `#` で始まるもの（ページ内の位置）は、`href` の規則によらずに許す。`img`・`iframe`・`source`・`track` は、`src` が無いか合わないときは、要素を取り除く（`data:` の画像も取り除く。6.12の24）。

| 種類 | 属性 | 許すもの |
| --- | --- | --- |
| リンク | `a` の `href`、`blockquote`・`del`・`ins` の `cite` | `http`・`https`・`mailto`・`tel` のURL、`/` で始まるサイト内のパス、`#` で始まるページ内の位置 |
| 画像 | `img` の `src` | `http`・`https` のURL（外部の画像は6.12の99）、`/` で始まるパス |
| 動画・音声 | `video`・`audio`・`source`・`track` の `src`、`video` の `poster` | `https` のURL、`/` で始まるパス |
| iframe | `iframe` の `src` | `https` のURL |

- URLの書き方：残したURLは、リンクの `href` と同じく、`/` で始まるパスにはサイトのURLのパスを前に付け、6.5.2のとおりエンコードする（`https://example.com/blog` のサイトでは、`<img src="/media/製品.jpg">` は `<img src="/blog/media/%E8%A3%BD%E5%93%81.jpg">`）。
- `class`：本体が値から作るクラスの形（`b-` と英数字8文字、`hl-` と16進数8桁。6.5.3の出力）のクラスは、ASCIIの大文字と小文字を区別せずに取り除く（互換モードのページでは、クラスを大文字と小文字を区別せずに照合するため）。ほかのクラスは残し、区切りの空白は1つにする。
- `id`：アンカーの名前の規則（ASCIIの英数字・`-`・`_`。6.7）に合い、同じHTMLの中で最初のもので、文書（6.5.1）のほかのアンカー（文書のどこかのブロックの `anchor`、前の見出しの自動のアンカー、前の `html`・`legacy` で残した `id`）と同じでないものだけを残す（構文解析は、閉じていない `b` などを後ろに写すことがあり、写した要素も同じ `id` を持つ）。後ろの見出しの自動のアンカー（6.5.1）は、残した `id` も避ける。
- `target`：`_blank`（ASCIIの大文字と小文字は区別しない）だけを残して `_blank` と書き、6.5.2の `newTab` と同じく、`rel` の先頭に `noopener` を置く。
- `rel`：`nofollow`・`sponsored`・`ugc`・`noopener`・`noreferrer` だけを、小文字にして残す（同じものは1つにする）。
- 書き出し：残した木を、HTMLにして出力する。属性は、書いた順に、値を `"` で囲んで書く。文字と属性の値は、6.5.2の文字と同じくエスケープする（`&`・`<`・`>` と、属性の値では `"`・`'` も。U+0000はU+FFFDにする）。中身が改行で始まる `pre` は、開始タグの後ろに改行を1つ足す（構文解析は、開始タグの直後の改行を1つ捨てるため）。
- 安定した形：タグだけを取り除くと、解析し直したときに違う木になる形が残ることがある（`p` の中の `div` など）。そこで、出力したHTMLを解析し直して、同じ規則でサニタイズし、変わらなくなるまで繰り返す（4回まで）。出力は、ブラウザーと同じく解析すると、出力した木になり、もう一度サニタイズしても、取り除くものが無い（既知の攻撃の例と、ファズテストで確かめる）。
- 上限：HTMLの仕様の構文解析は、入力によっては、長さの2乗に比例する時間がかかる。そこで、入力の長さ（バイト数）n から、構文解析の上限（木のノードは n+1024 個、手数は 64n+65536）と、出力の長さの上限（16n+64KiB）を決める。ノードは、要素・テキストなどと、要素の属性を1つずつ数え、手数は、字句・ノードと、開いた要素の列などを調べた数を数える。解析し直すときの上限は、n と出力の長さの小さいほうから決める。値は仮のもの（6.12の9）。
- サニタイズできないもの：上限を超えるもの（`/12/attrs/html: the HTML is too complex to sanitize; not rendered`）と、4回で変わらなくならないもの（`/12/attrs/html: the HTML cannot be sanitized into a stable form; not rendered`）は、描画せず（何も出力せず、ページのCSSにも規則を書かない）、ブロックのほかの警告を出さずに、この警告だけを示す。
- 囲み：サニタイズしたHTMLは、前後のASCIIの空白を除いて出力する。ブロックに `id` か `class`（上記の「`id` と `class`」）があるときだけ、`<div id="…" class="…">` で囲み、開始タグの後ろと終了タグの前で改行する（HTMLが空なら `<div id="…"></div>`）。無いときは、HTMLだけを出力する（空なら、何も出力しない）。
- 警告：サニタイズで取り除いたものと変えたものは、`<ブロックのパス>/attrs/html` の位置で、ブロックのバリエーションと `style` の警告の後ろに、最初に起きた順に警告する。同じ文のものは1つにして、2回以上のものには ` (N times)` を付ける（`/3/attrs/html: removed onclick attribute of <p> (3 times)`）。文は、1つのブロックで100種類までで、超えた分は `and N more changes` の1つにまとめる。文の中の名前と値は、64バイトを超えるものを64バイトまで（文字の途中では切らない）にして、`...` を付ける。要素の文は `removed <script> element and its content`（終了タグの無い要素は `removed <input> element`）・`removed <font> element, keeping its content`・`removed elements nested more than 256 deep, keeping their content`・`changed <h1> to <h2>`・`removed <img> element: missing src`・`removed the content of <iframe>`、属性の文は `removed style attribute of <p>`・`removed href attribute of <a>: invalid URL "javascript:alert(1)": scheme "javascript" is not allowed`・`removed id attribute of <h2>: anchor "intro" is already used`・`removed class "b-0paragr1" of <div>: reserved for the core`・`removed target attribute of <a>: only _blank is allowed`・`removed rel value "external" of <a>` など。
- ショートコード：ショートコード（`[gallery ids="1,2"]` など。6.10.3）は、解釈せずに、書いたままの文字として出力する。

#### 6.5.6 拡張ブロック（サイトで定義する）

コアにないブロックは、サイト設定で定義する（案。開発者が書くスキーマのファイル（6.6.8）に書く。`blocks` の読み込みは、拡張ブロックと合わせて作る）。**定義（スキーマ）はサイト設定、描画はテーマ**が受け持つ。属性は、カスタムフィールドと同じ型で定義する。

```yaml
# 例：吹き出し
blocks:
  speech:
    label: 吹き出し
    attrs:
      name: { type: text, label: 話す人, maxLength: 30 }
      icon: { type: media, accept: [image] }
      side: { type: select, options: [left, right], default: left }
    content: inline       # 中身は文中装飾つきのテキスト
    supports: [textColor, backgroundColor, border]   # 使える見た目の項目
```

テーマに描画テンプレートが無い場合は、ビルド時に警告し、中身のテキストだけを既定の形で表示する。

#### 6.5.7 あえて持たないもの

| 持たないもの | 理由・代わり |
| --- | --- |
| 生のCSS（`style` 属性の文字列やCSSのコード） | 書式を検証できず、表示の改ざんや崩れの原因になるため。6.5.3の型付きの値で表す |
| 改ページ（`<!--nextpage-->`） | 利用が少ないため |
| 汎用のクエリーループ | 条件を絞った `postList`（段階2）で代える |
| ナビゲーション、ロゴ、ウィジェットなど、サイト全体の部品 | テーマとサイト設定が受け持つ |
