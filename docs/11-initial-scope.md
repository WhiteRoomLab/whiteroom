## 11. 初期実装の範囲（提案）

| 機能 | 優先度案 | 状態 |
| --- | --- | --- |
| Linuxへインストール可能なCMS本体 | 必須 | 要件・実装言語（Go）は決定。コマンド `whiteroom` の `build`・`serve public` を作った（9.4。名前とサブコマンドの形は決定済み。9.1）。ほかのコマンドと管理画面は、まだ無い |
| 専用Content Store（自作の保存の層） | 必須 | **構成採用済み**。保存先（3.4）を、自作の保存の層（3.5）の上に作った（文書とリビジョンをCASに置くことなどは決定済み。3.1）。索引（3.4）と、保存の操作（6.7）も作った。保存先からのビルドと、公開の操作は、まだ無い |
| 記事・固定ページの編集 | 必須 | 要件決定 |
| コンテンツモデル（ブロックの語彙） | 必須 | 方針決定。語彙・検証・描画は6章の案で作った（一部は決定済み。6.1） |
| 静的HTMLへのビルド・公開 | 必須 | 方式決定。ビルド（4.3）と公開用の内蔵サーバー（9.5）を作った（リリースの切り替えなどは決定済み。4.1）。トリガー（保存と公開の分け方）は未決定（12章の論点4） |
| ファイルベースのテーマ | 初期実装 | 方向性として合意。形式は5.4の案で作った（設定ファイルとテンプレートの名前などは決定済み。5.1） |
| 管理画面と管理ユーザー機能 | 必須 | 要件決定 |
| ログイン履歴・アクティビティログ | 必須 | 要件決定 |
| お問い合わせ | 必須 | 要件決定。フォームの定義と描画は6.6.5の案で作った。送信を受け付ける処理（8章）は、まだ無い |
| 画像・メディア管理 | 高 | 一部は決定済み（形式を中身から決めること、画像の原本を公開しないことなど。6.1・3.1）。ほかは6.6.2の案で作った。メディアの追加・差し替え・保存・削除の操作（6.6.2・6.7）も作った。HTTPのアップロードと管理画面は、まだ無い |
| 下書き・プレビュー・公開ロールバック | 高 | 提案段階。エントリーの状態（6.4.1）と、リリースの切り替えと1つ前のリリースを残すこと（4.3）はある。プレビューと戻す操作（6.12の108）は、まだ無い |
| WordPressからの取り込み | 高 | 提案段階。WXRの読み込み・取り込みレポート・IDの割り当てを作った（6.10.5）。変換とコマンドは、まだ無い |
| ブロックエディタ | 検討 | 提案段階 |
| 独自コンテンツDSL・コンパイラ | 対象外（当面） | **採用しない**ことに決定 |
| テーマ設定GUI・レイアウト編集 | 将来拡張 | 方向性として合意 |
| 独自データストアエンジン | 必須 | 保存の層を、自作のエンジン（3.5）に替えた（決定済み。3.1）。本番で使う前に要るもの（6.12の129〜131）は、まだ無い |
