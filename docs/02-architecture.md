## 2. 全体アーキテクチャ（概念）

以下は**決定済みの要件を満たすための構成例**であり、サービス分割・具体的なプロセス構成・使用ライブラリはまだ確定していない。

```text
                 ┌──────────────────────────┐
                 │ CMS 管理画面 / 管理 API   │  ← 動的・認証あり
                 │ 記事編集 / ユーザー管理   │
                 └────────────┬─────────────┘
                              │
               ┌──────────────┴─────────────┐
               ▼                            ▼
       ┌──────────────────┐      ┌────────────────────┐
       │ SQLite           │      │ 専用 Content Store │
       │ ユーザー・権限   │      │ 記事・ページ・画像 │
       │ ログイン履歴     │      │ 履歴・スナップショット│
       │ アクティビティ   │      └──────────┬─────────┘
       │ 監査データ       │                 │
       └──────────────────┘                 ▼
                                  ┌─────────────────┐
                                  │ 静的ビルド      │
                                  │ HTML/CSS/資産   │
                                  └────────┬────────┘
                                           ▼
                                  ┌─────────────────┐
                                  │ 公開Webサーバー │  ← 原則静的
                                  └─────────────────┘
                                           ▲
                                           │
                        一般閲覧者 ────────┘
                              │
                              ▼
                      ┌──────────────────┐
                      │ お問い合わせ API │  ← 限定的な動的処理
                      └──────────────────┘
```

※ SQLiteの各種テーブル、Content Storeのデータ種別、お問い合わせデータの保存場所は**例示**であり詳細設計ではない。
