### 6.8 描画の取り決め（Renderer）

- **文中の装飾はCMS本体がHTMLに変換し、テーマには変換済みの安全なHTMLとして渡す。** テーマは生の文字列を扱わないため、エスケープやURL検証の漏れが起きにくい（変換の規則は6.5.2）。
- ブロックごとに、テーマのブロックのテンプレート（`blocks/image.html` など。5.4.4）で描画する。テーマに無いものは、本体の既定のテンプレート（`internal/render/blocks/`。出力するHTMLは6.5.4・6.6.5）を使う。既定のテンプレートは、本体が足す関数（5.4.5）を使わないので、テーマの `blocks/` にそのまま置け、書き換える元にできる（テストでは、`blocks/` にコピーしたテーマでも、同じHTMLになることを確かめる）。`html`・`legacy` は、テンプレートを使わず、本体がサニタイズしたHTMLを出力する（6.5.4）。
- テンプレートには、検証済みの表示用データだけを渡す（参照はURLなどに解決済みの状態にする。ブロックのテンプレートとページのテンプレートのデータは5.4.4）。テンプレートで使える関数は、5.4.5のものだけにする。
- 参照の解決（案）：描画は、本文などが参照するエントリー（タイトルと、ページのパス。公開していなければパスは無い）・メディア（公開するファイルのパス）・フォームを、ビルドが渡す照会の関数で調べる。画像のメディアは、表示する大きさ（テーマのサイズか、既定の大きさ）ごとのファイル（`src` のパスと、それを表示する幅と高さ、`srcset` のファイルのパスと幅）も調べる（6.5.4）。パスは、出力するパス（6.6.8）と同じく、サイトのURLからのパスにする（サイトのURLのパスは、描画が前に付ける。6.5.2）。画像のファイルのパスには、版の `?v=` が付く（6.6.2）。描画はファイルを作らず、ファイルは、ビルドが作って出力する（6.6.2）。
- 見た目（案）：描画は、HTMLと一緒に、そのHTMLに要るページのCSS（6.5.3の出力）を返す（1つの文書（本文と `blocks` 型のフィールド）と、`richText` 型のフィールドなどの文中装飾ごとに。ビルドは、1つのページに出すものを合わせ、同じ規則を1回だけ書く）。`style` と、長さと数の見た目の属性は、ブロックの規則にして、規則のあるブロックだけに `b-9x3v7k5m` のようなクラスを付ける。選択肢の決まった見た目の属性は、決まったクラスにし（6.5.4）、`highlight` の色は、`hl-` のクラスの規則にする（6.5.2）。バリエーションは、決まった形のクラス名（例：`is-variant-box`）として出力する（テーマに無いものは付けない。6.5.4）。
- ブロックのID（案）：規則のあるブロックのうち、IDの正しくないものと、規則のある前のブロック（文書の中の、ほかの列のものも）と同じIDのもの（どちらも検証を通っていないもの）は、規則を捨てて、`b-` のクラスを付けずに描画し、そのブロックのほかの警告より前に、`id` の位置で警告する（`/0/id: invalid block ID "b_x"; rendered without its CSS`、`/5/id: duplicate block ID "b_0paragr1"; rendered without its CSS`）。規則の無いブロックは、IDを確かめず、重なりにも数えない。ほかの文書のブロックとの重なりは、避けない（6.12の89）。
- 警告（案）：描画は、テーマに無いバリエーション、テーマが許さない見た目の値（6.5.3）、リンクにできないリンク（6.5.2）、`alt` の無い画像、テーマに無い画像のサイズとファイルの無い画像（6.5.4）、`html`・`legacy` のサニタイズで取り除いたもの（6.5.4）、描画しないブロック（6.5.4）などを、エラーにせずに警告して、描画を続ける（6.2の4）。警告は英語の文で、ブロックの列（または文中装飾）の中の位置を表すJSON Pointer（RFC 6901）を前に付け（`/9/variant: the theme has no separator variant "wide"; rendered without its class`）、文書の中の順に並べる。本文と `blocks` 型のフィールドを一緒に描画したときは、どの列のものかも示す。ビルドでの示し方は、下記の「警告の位置」（どの警告で公開を止めるかは6.12の82）。テーマのテンプレートの実行のエラー（データに無い項目を読むものなど。5.4.4）は、警告ではなく、描画のエラーにする。
- 構造化データ（JSON-LD）やOGPはモデルから自動で生成し、本文には持たない（ビルドでの出力は、下記の「`<head>`」と「構造化データ」）。
- 多言語：`<html lang>`、翻訳版どうしの `hreflang`、サイトマップでの言語の対応を出力する（`<html lang>` は、テーマが書く。5.4.9）。言語の切り替えに使う「現在のページの翻訳一覧」をテーマに渡す（ビルドでの決め方は、下記の「言語の対応」）。テーマ内の固定の文言（「続きを読む」など）は、テーマの翻訳ファイル（5.4.6）で扱う（翻訳の無い文言の警告は、下記の「警告の位置」）。

ページの描画（案）：

- ビルド（4.3）は、ページ（6.6.8の「ビルドで出力するページ」）ごとに、テーマのページのテンプレート（5.4.4の表）を、ページのテンプレートのデータ（5.4.4）で実行して、ページのファイルに書く。言語ごとに、テーマの文言の言語（5.4.6）と、URLの前に付けるサイトのURLのパス（6.5.2）を決めて描画する。いくつかのページを同時に描画する（4.3の `Workers`）が、どの数でも、同じファイルと警告になる。
- エントリーの本文：本文と `blocks` 型のフィールドは、1つの文書（6.5.1）として、まとめて描画する。順は、本文、`blocks` 型のフィールド（タイプの定義の順で、グループとリストの中も、その場所で深さ優先に）で、その後に、`richText` 型のフィールドを同じ順に描画する。この順で、見出しの自動のアンカーの `-2` など（6.5.1）と、ページのCSSの規則の順（文書の規則、`richText` 型のフィールドの `highlight` の規則の順）が決まる。描画したHTMLは、ページのデータの `.Entry.Body` と `.Entry.Fields`（5.4.4）で渡す。
- 一度だけ作るもの：投稿ページの本文は、一覧のどのページにも出すので、1回だけ描画する。一覧に並べるエントリーのデータ（本文の無いもの。5.4.4の `.Entries`）も、エントリーとページの言語ごとに1回だけ作り、それを並べるどの一覧でも使う。
- ページのCSS：エントリーのページと、投稿ページの一覧のページでは、そのエントリーの本文とフィールドのCSS（6.5.3の出力）を、同じ規則を1回だけ書いて合わせたものを、ページのCSSにする（ファイルは6.6.8の「ほかの出力」）。規則が無ければ、ページのCSSは無い。ほかのページ（ほかの一覧と、見つからないページ）にも無い（一覧のエントリーには、本文が無いため）。
- 失敗：テンプレートの実行のエラー（5.4.4）では、ビルドは失敗する。エラーの文は、ページのテンプレートのものは `page <パス>: ` の後ろに、ブロックのテンプレートのものは、エントリーの公開したリビジョンのファイルの後ろに、`html/template` のエラーを続けたもの（`revisions/rev_….json: template: blocks/paragraph.html:1:5: executing "paragraph.html" at <.Text>: can't evaluate field Text in type render.Paragraph`。ビルドのエラーでは、前に `rendering the pages: ` が付く。4.3の「エラーと警告」）。いくつかのページで失敗したときも、ワーカーの数によらず、決まった順で最初のページのエラーを返す。

タイトルと説明（案）：

- `<title>` のタイトル（`.PageTitle`）：
  - トップページ（`frontPage` の固定ページと、最新の投稿の一覧のどのページも）と、見つからないページは、その言語のサイト名だけ（タイトルの書式を使わない）。
  - ほかのページは、その言語のタイトルの書式（6.6.8の `seo.titleFormat`。無ければ `{title} | {siteName}`）の `{siteName}` に、その言語のサイト名を、`{title}` に次のものを入れる。エントリーのページと投稿ページ（一覧のどのページも）は、エントリーの `seo.title`（6.4.2）、無ければ `title`。タームの一覧は、タームの `name`。カスタムタイプの一覧は、タイプの `label`（無ければ名前。言語で分けない）。著者ページは、著者の `name`。2つの置き換えは一度に行うので、タイトルの中の `{siteName}` などの文字は、そのまま残る。
  - 2ページ目からの一覧は、1ページ目と同じタイトル（ページの番号は入れない。6.12の61）。
  - 例（6.11の見本のサイト。書式は、日本語が `{title}｜{siteName}`、英語が `{title} | {siteName}`）：`/about/` は `会社概要｜株式会社〇〇`、`/news/` と `/news/page/2/` は `お知らせ｜株式会社〇〇`、`/author/yamada/` は `山田 太郎｜株式会社〇〇`、`/en/about/` は `About us | Example Inc.`、`/` と `/404.html` は `株式会社〇〇`、`/en/` と `/en/page/2/` は `Example Inc.`（見本のテーマの `404.html` は、`.PageTitle` を使わずに、自分でタイトルを書く。5.4.9）。
- ページ自体のタイトル（`.Title`）：エントリーの `title`（`seo.title` ではない。`frontPage` の固定ページと投稿ページも）、タームの `name`、タイプの `label`（無ければ名前）、著者の `name`。トップページの最新の投稿の一覧（どのページも）と、見つからないページでは空（テーマが書く）。
- 説明（`<meta name="description">`・`og:description`・構造化データの `description`）：
  - エントリーのページ（`frontPage` の固定ページと、投稿ページの一覧のどのページも）は、エントリーの `seo.description`、無ければ `excerpt`、無ければ自動の抜粋（下記）。
  - タームの一覧はタームの `description`、著者ページはページの言語の `bio`、トップページの最新の投稿の一覧（どのページも）はその言語の `tagline`。カスタムタイプの一覧と、見つからないページには無い。
  - 一覧のどのページも、1ページ目と同じ説明にする。
  - 1行にする：空白の続くところ（改行・タブ・全角スペースなど、Unicodeの空白）を1つの空白にし、両端の空白を除く（`seo.description` と `tagline` も。6.11.3のカテゴリー「お知らせ」の、改行で2行にした `description` は、`会社からのお知らせです。 新しいサービスやイベントの情報を掲載します。`）。空になれば、説明は無い。
- 自動の抜粋（6.12の120）：`excerpt` の無いエントリーの抜粋。ページのデータの `.Excerpt`（5.4.4）、説明（上記）、フィードの項目の `description`（下記の「フィード」）に使う。
  - 本文だけから作る（フィールドからは作らない）。`paragraph`・`heading`・`tableCell` の文字と、`quote` の `citation`（引用の中身の後）を、本文の順に使う。`list`・`listItem`・`quote`・`table`・`tableRow`・`columns`・`column`・`group` は、中のブロックを見る。`image`（`alt` とキャプション）・`buttons`・`button`・`separator`・`spacer`・`code`・`embed`・`file`・`form`・`html`・`legacy` と、表のキャプションは使わない。
  - 1つのブロックの中の文字は、そのままつなぎ（装飾は何も足さない。`株式会社` と太字の `〇〇` は `株式会社〇〇`）、`hardBreak` は空白にする。ブロックの間には空白を入れ、説明と同じく1行にする（段落の始めの全角スペースは消える）。
  - 長さは120文字（コードポイント）まで。それより長ければ、最初の120文字から後ろの空白を除いたものに、`…`（U+2026）を付ける。本文の無いものは空。例（6.11の見本のサイトの、2つの段落の投稿）：`11月5日に開かれるWeb制作のセミナーで、当社の山田が登壇します。テーマは、だれにとっても使いやすいWebサイトの作り方です。 アクセシビリティの基本から、制作の現場で気をつけていることまで、事例を交えてお話しします。オンラインでも参加で…`。

言語の対応（案）：

- ページの、サイトの言語ごとの「対応するページ」から、言語の切り替えに使う「現在のページの翻訳一覧」（`.Translations`。5.4.4）と、`hreflang`（下記の「`<head>`」）と、サイトマップの言語の対応（下記の「サイトマップ」）を作る。
- ページ自身の言語では、ページ自身（2ページ目からの一覧も）。見つからないページでは、その言語のトップページ。
- ほかの言語では、次のもの。
  - トップページ（`frontPage` の固定ページと、最新の投稿の一覧のどのページも）と、見つからないページ：その言語のトップページ（いつもある）。
  - エントリーのページと投稿ページ（一覧のどのページも）：同じ翻訳グループ（6.4.5）の、その言語の公開しているエントリーのページ（`frontPage` のものは言語のパス、`postsPage` のものは一覧のパス）。下書きなど、公開していないものは数えない。
  - タームの一覧：同じ翻訳グループの、その言語のタームの一覧。
  - カスタムタイプの一覧と著者ページ：その言語の、同じタイプの一覧と、同じ著者の著者ページ（いつもある）。
  - 2ページ目からの一覧：1ページ目に対応するページ（ほかの言語の一覧の1ページ目）。
- 対応するページの無い言語では、その言語のトップページを示し、無いことを印にする（`.Missing`。6.4.5の「翻訳が無い場合」）。
- 例（6.11の見本のサイト）：`/about/` と `/en/about/`、`/` と `/en/`、`/works/` と `/en/works/`、`/author/yamada/` と `/en/author/yamada/` が対応する。英語の翻訳の無い `/services/` と、英語の翻訳の無い投稿ページ（固定ページ「お知らせ」）の `/news/page/2/` では、英語は無い（`/en/` を示す）。`/en/page/2/` の日本語は `/`。

`<head>`（案）：

- テーマが書くもの：`<html lang>`（ページの言語。`.Language`）、`<meta charset>` などの要素、`<title>`（`.PageTitle` か、テーマが作るもの）、CSSの `<link>`（サイトのCSS・テーマのCSS・ページのCSSの順。6.5.3の「読み込む順」）と、本体の作るもの（`.Head`）。例は5.4.9。
- 本体の作るもの（`.Head`）：次の要素を、この順に、1行に1つ書く（あるものだけ。行は改行でつなぎ、最後の行の後ろには改行を付けない）。テーマによらない。
  1. 説明（上記の「タイトルと説明」）：`<meta name="description" content="…">`。
  2. 正規URL（下記）：`<link rel="canonical" href="…">`。見つからないページには無い。
  3. robots（下記）：`<meta name="robots" content="noindex">`。
  4. 言語の対応（下記）：`<link rel="alternate" hreflang="<言語コード>" href="…">` を言語ごとに、その後に `hreflang="x-default"` のもの。
  5. フィード：`<link rel="alternate" type="application/rss+xml" title="<サイト名>" href="<フィードのURL>">`。ページの言語のサイト名と、ページの言語のフィード（6.6.8の「ほかの出力」）のURL（フィードの `atom:link` と同じもの）。どのページにも（見つからないページにも）書く。
  6. アイコン（下記）。どのページにも書く。
  7. OGPとTwitterのカード（下記）。見つからないページには無い。
  8. 構造化データ（下記の「構造化データ」）。見つからないページには無い。
- URL：どれも、サイトのURL（6.6.8の `url`）を前に付けた絶対URLで、ページのURLと同じく、1回だけエンコードする（6.5.2。すでにある `%XX` はそのままなので、`/会社/` と `/%E4%BC%9A%E7%A4%BE/` は同じURLになる）。
- 属性の値：`&`・`<`・`>`・`"`・`'` を、`&amp;`・`&lt;`・`&gt;`・`&#34;`・`&#39;` にする（`Q&A: "<b>"` というタイトルは `content="Q&amp;A: &#34;&lt;b&gt;&#34;"`、`?a=1&b=2` のあるURLは `href="…?a=1&amp;b=2"`）。
- 見つからないページの `.Head` は、robots・フィード・アイコンの行だけ。
- 使う画像：アイコン・OGPの画像・ロゴ（構造化データの `publisher`）・著者のアバター（著者ページの構造化データ）は、テンプレートが表示しなくても公開する（6.6.2の「ビルドで公開するもの」）。

- 正規URL：
  - エントリーのページ（`frontPage` の固定ページも）は、エントリーの `seo.canonical`（6.4.2）、無ければページのURL。`seo.canonical` のパスは、サイトのURLからのパス（6.12の56。`https://example.com/blog` のサイトの `/about-us/` は `https://example.com/blog/about-us/`）で、クエリとフラグメントも残し、サイトのページかは確かめない。URLは、書いたものをエンコードしたもの（`https://other.example/会社/?q=a&r=b` は `href="https://other.example/%E4%BC%9A%E7%A4%BE/?q=a&amp;r=b"`）。

- robots の noindex：サイト設定の `seo.noindex`（6.6.8）ならすべてのページに、エントリーの `seo.noindex`（6.4.2）ならそのページ（投稿ページでは、一覧のどのページにも）に、見つからないページにはいつも書く。ほかの行（正規URL・言語の対応・OGP・構造化データ）は変えない。サイトマップには載せない（6.6.8）。
- 言語の対応（`hreflang`）：
  - 1ページ目（2ページ目からの一覧と、見つからないページには書かない）で、ほかの言語に対応するページ（上記の「言語の対応」）が1つでもあるときだけ書く。
  - 対応するページのある言語ごとに、設定の `languages` の順に（ページ自身の言語も）書き、その後に、既定の言語（`defaultLanguage`）の対応するページがあれば、それを `x-default` にする。`hreflang` の値は、設定の言語コードのまま（`en-US`・`zh-Hant`）。`prefixDefaultLanguage` のサイトでは、`x-default` は、既定の言語のページ（`/ja/…`）にする（`/` は、リダイレクト。6.6.6）。

  - 対応するページが、`noindex` のページ、正規URLがほかを指すページ、サイトマップに載せない一覧でも書く（6.12の118）。
- アイコン：サイト設定に `icon`（6.6.8）があれば、32・192・512画素のアイコン（6.6.2）の `<link rel="icon" href="…" sizes="<幅>x<高さ>" type="image/png">` を、この順に書き、その後に、180画素のアイコンの `<link rel="apple-touch-icon" href="…">` を書く。`sizes` はファイルの大きさで、同じになる行は1回だけ書く（64×64画素のPNGでは、`icon-32x32.png`（`32x32`）と、192画素と512画素の代わりの `icon.png`（`64x64`）と、apple-touch-icon の `icon.png`）。`favicon.ico` は作らない（6.12の58）。原本を調べられなければ、アイコンの行は無い（ビルドは、メディアの確かめで失敗する。6.6.2）。
- OGPとTwitterのカード（この順）：
  - `og:type`：投稿のページは `article`、ほかのページは `website`。
  - `og:title`：タイトルの書式の `{title}` に入れるもの（上記の「タイトルと説明」。サイト名は付けない）。トップページでは、その言語のサイト名（`frontPage` の固定ページの `seo.title` も使わない）。
  - `og:description`：説明があれば。`og:url`：正規URL。`og:site_name`：ページの言語のサイト名。
  - `og:image`・`og:image:width`・`og:image:height`・`og:image:alt`：OGPの画像の、公開するファイル（6.6.2）のURL（版の `?v=` 付き）と、ファイルの幅と高さ。`og:image:alt` は、メディアの `alt` のうち、ページの言語の値があるときだけ。OGPの画像は、エントリーの `seo.ogImage`、無ければエントリーの `featuredImage`（どちらも、エントリーのページと、投稿ページの一覧のどのページで）、無ければサイト設定の `seo.ogImage` のうちページの言語のもの（どのページでも）。どれも無ければ、`og:image` の行は無い。選んだ画像の原本を調べられなければ、次のものに代えずに、画像が無いものとする（ビルドは、メディアの確かめで失敗する。6.6.2）。
  - `twitter:card`：OGPの画像があれば `summary_large_image`、無ければ `summary`。
  - 書かないもの：`og:locale`（6.12の116）、`og:image:type`、`og:image:secure_url`、`article:` で始まるもの、ほかのTwitterのタグ。

構造化データ（案）：

- 見つからないページのほかのどのページにも、schema.orgの構造化データを、JSON-LDの `<script type="application/ld+json">` で1つ書く。1つのオブジェクトを、空白と改行を入れずに1行で書き、`"@context":"https://schema.org"`、`"@type"` の後に、下の表の項目を、この順に並べる。値の無い項目（表の「あれば」）は書かない。
- 文字列は、JSONの文字列にして、`<`・`>`・`&` を、Unicodeのエスケープ（バックスラッシュと `u` と、16進4桁の `003c`・`003e`・`0026`）で書く（`</script>` や `<!--` が、中に現れないように）。ほかの文字（日本語など）は、そのまま書く。

警告の位置（案）：

- ビルド（4.3）は、描画などの警告を、エラーと同じ形（ファイル・行・列・JSON Pointer・英語の文。4.3の「エラーと警告」）で示す。行と列は、JSON Pointer の指す項目のもの（無ければ、いちばん近い親のもの。列の要素では、その `{`）。同じ警告は、何回出ても1回だけ示す（いくつかのページや一覧、フィード（下記）で描画したエントリーのものも）。
- エントリーの描画の警告は、公開したリビジョンのファイルの、本文のものは `/body`、`blocks` 型のフィールドのものは `/fields/<名前>` の後ろに、ブロックの列の中の位置（上記の「警告」）を続けた位置にする。グループの中のフィールドは `/fields/<グループ>/<フィールド>/…`、リストの項目は `/fields/<リスト>/<番号>/…`（グループのリストでは `/fields/<リスト>/<番号>/<フィールド>/…`）、`richText` 型のフィールドは、文中装飾の中の位置（`/fields/<名前>/<番号>/marks/<番号>` など）。例：`revisions/rev_….json:28:9: /fields/details/1/variant: the theme has no paragraph variant "wide"; rendered without its class`、`revisions/rev_….json:103:15: /fields/variants/1/description/0/marks/0: the theme has no highlight variant "neon"; rendered without its class`。
- ほかの警告の位置：`link` のフィールドは、フィールドの位置（5.4.4）。テーマに無いページのテンプレートは、リビジョンの `/template`（5.4.4）。メニューは、メニューの文書（6.6.4）。リダイレクトは、リダイレクトの文書（6.6.6）。メディアの原本は、メディアの文書（6.6.2）。サイトマップに載せないページは、ページの元（6.6.8）。NginxとApacheの設定に書けないサイトのパスは、設定の文書の `/url`（6.6.6）。
- テーマの文言：ページの言語の翻訳に無く、既定の翻訳の文言を使うキー（5.4.6）は、言語ごとに1つ、ファイルを `theme` にして（行と列は無い）、キーを既定の翻訳の順に並べて警告する（`theme: no translation in en for the key "postedBy"; pages in en use its text in ja, the default language of the theme`。キーが2つ以上なら `theme: no translation in en for the keys "postedBy", "readMore"; pages in en use their texts in ja, the default language of the theme`）。言語コードの最後の部分を順に除いた言語のファイル（5.4.6）にあるキーと、既定の翻訳の言語のページと、翻訳ファイルの無いテーマでは、警告しない。

フィード（案）：

- 言語ごとのRSS 2.0のフィード（パスとファイル、載せる投稿は、6.6.8の「ほかの出力」）。
- XMLのファイル（フィードとサイトマップ）：UTF-8で、`<?xml version="1.0" encoding="UTF-8"?>` と改行で始め、1行に1つの要素を、字下げせずに書き、改行で終える（本文のHTMLのように、改行のある文字は、その行数になる）。ビルドした日時など、ビルドごとに変わるものは書かないので、同じサイトからは、同じバイト列になる。
- 最上位：`<rss version="2.0" xmlns:content="http://purl.org/rss/1.0/modules/content/" xmlns:dc="http://purl.org/dc/elements/1.1/" xmlns:atom="http://www.w3.org/2005/Atom">`（1行）と、`<channel>`。
- `channel`（この順）：`title`（その言語のサイト名）、`link`（その言語のトップページの絶対URL）、`description`（その言語の `tagline`。無ければサイト名。RSSでは必須のため）、`language`（設定の言語コードのまま。`ja`・`en-US`）、`<atom:link href="<フィードのURL>" rel="self" type="application/rss+xml"/>`、項目。`lastBuildDate`・`pubDate`・`ttl`（ビルドした日時によらないように）と、`generator`・`image`・`copyright`・`managingEditor`・`webMaster`・`docs`・`cloud` は書かない。
- `item`（投稿ごとに。この順に、値のあるものだけ）：
  - `title`：投稿の `title`（`seo.title` ではない）。
  - `link`：投稿のページの絶対URL。
  - `<guid isPermaLink="false">`：エントリーのID。スラッグやURLの規則を変えて、投稿のURLが変わっても変わらないので、フィードのリーダーは、その投稿を、新しいものとして示さない。
  - `pubDate`：`date` を、サイトのタイムゾーン（`timeZone`）にして、RFC 1123の形（数の時差と、英語の曜日と月）で書く（`Mon, 26 Oct 2026 00:30:00 +0900`）。ほかの時差で書いた `date` も直す（タイムゾーンが `Asia/Tokyo` のサイトの `2026-10-25T15:30:00Z` は `Mon, 26 Oct 2026 00:30:00 +0900`。ページの `.Date` と、構造化データの `datePublished` と同じ）。
  - `dc:creator`：著者の `name`（`author` の無い投稿には無い）。RSSの `author` は、メールアドレスを書く要素なので、使わない。
  - `category`：投稿のタームごとに1つ、タームの `name`。タクソノミーは、タイプの順（`category`・`tag`・スキーマで足したもの）で、タームは、リビジョンに書いた順。祖先のタームは入れず、`domain` の属性は付けない。
  - `description`：抜粋（`excerpt`、無ければ自動の抜粋。`seo.description` ではない）を、説明（上記）と同じく1行にしたもの。RSSは、項目の `description` をHTMLとして読むので、`&`・`<`・`>` を、まずHTMLの `&amp;`・`&lt;`・`&gt;` にしてから、XMLとしてエスケープする（`1 < 2 & 3` は `<description>1 &amp;lt; 2 &amp;amp; 3</description>`）。抜粋が空なら無い。
  - `content:encoded`：本文（`body`）のHTML。CDATAではなく、エスケープしたXMLの文字で書く。本文が空なら無い。
  - `author`・`comments`・`enclosure`・`source` は書かない。
- 本文のHTML：ページと同じテーマのブロックのテンプレートと、同じ自動のアンカーで描画したもの。ただし、URLの前に、サイトのURL（`https://example.com/blog`）を付けて描画し直すので、本体の作るURL（エントリーとメディアへのリンク、`/` で始まる `href`（`/about/` は `https://example.com/blog/about/`）、画像の `src`・`srcset`、`file` ブロック、フォームの送り先とプライバシーポリシーへのリンク、ブロックのテンプレートの `asset` のURL）は、絶対URLになる。ほかのサイトのURLは、そのまま。`anchor` だけのリンク（`#top`）は、そのまま残る（6.12の119）。ページのCSS（6.5.3の出力）はフィードに入らない（HTMLのクラスは残る）。
- 描画し直したときの警告は、ページのものと同じで、1回だけ示す（上記の「警告の位置」）。ブロックのテンプレートの実行のエラーでは、ページと同じく、ビルドは失敗する。
- エスケープ（フィードとサイトマップ）：
  - 属性の値（`"` で囲む）：`&`・`<`・`>`・`"`・`'` を `&amp;`・`&lt;`・`&gt;`・`&quot;`・`&apos;` に、タブ・LF・CRを `&#x9;`・`&#xA;`・`&#xD;` にする（属性の値の中では、空白として読まれるため）。
  - HTMLを入れる要素（項目の `description` と `content:encoded`）と、サイトマップの `loc`：`&`・`<`・`>` を `&amp;`・`&lt;`・`&gt;` に、CRを `&#xD;` にする（引用符・タブ・LFは、そのまま）。
  - フィードのほかの要素（HTMLでない文字。`title`・`link`・`channel` の `description`・`language`・`guid`・`pubDate`・`dc:creator`・`category`）：`&`・`<`・`>` を、16進の文字参照の `&#x26;`・`&#x3C;`・`&#x3E;` に、CRを `&#xD;` にする（`<title>Q&#x26;A</title>`。RSS Best Practices Profile が、多くのリーダーが文字として示す形として勧めるもの）。

サイトマップ（案）：

- 載せるページと、ファイルの分け方は、6.6.8の「ほかの出力」。XMLの書き方とエスケープは、フィード（上記）と同じ。
- `<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9" xmlns:xhtml="http://www.w3.org/1999/xhtml">`（`xhtml` の名前空間は、いつも書く）の中に、ページごとに、`<url>`、`<loc>`（ページの絶対URL。正規URL・`og:url` と同じもの）、ページの `<head>` の言語の対応（上記）と同じものの `<xhtml:link rel="alternate" hreflang="<言語コード>" href="<URL>"/>`、`</url>` を書く。言語の対応には、サイトマップに載せないページ（`noindex` のページ、正規URLがほかを指すページ、エントリーの無い一覧）も出る（見本のサイトの `/works/` は、エントリーの無い `/en/works/` を示す。6.12の118）。
- 順：`loc` の順（エンコードしたURLのバイト列の順。`/2026/…` は `/about/` より、`/en/…` は `/news/` より、`/works/` は `/works_category/…` より前）。
- 書かないもの：`lastmod`（更新した日時が無いため。6.12の26）、`changefreq`、`priority`。
- 載せるページが無ければ、`url` の無い `urlset` になる（6.12の114）。
- 例（6.11の見本のサイトの `/sitemap.xml` の始め）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9" xmlns:xhtml="http://www.w3.org/1999/xhtml">
<url>
<loc>https://example.com/</loc>
<xhtml:link rel="alternate" hreflang="ja" href="https://example.com/"/>
<xhtml:link rel="alternate" hreflang="en" href="https://example.com/en/"/>
<xhtml:link rel="alternate" hreflang="x-default" href="https://example.com/"/>
</url>
<url>
<loc>https://example.com/2026/10/01/renewal/</loc>
</url>
…
</urlset>
```

- 分けたとき（6.6.8）：`sitemap.xml` は、分けたファイルを順に並べたサイトマップのインデックスにする（絶対URLで、`lastmod` は書かない。インデックスは分けない）。例（`https://example.com/blog` のサイトを2つに分けたとき）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
<sitemap>
<loc>https://example.com/blog/sitemap-1.xml</loc>
</sitemap>
<sitemap>
<loc>https://example.com/blog/sitemap-2.xml</loc>
</sitemap>
</sitemapindex>
```
